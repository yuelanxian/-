# 07 · 备份与恢复

Nextcloud 里的照片和文件是你的"主数据"，**它本身不是备份**：硬盘坏了、误删了、被勒索病毒加密了，Nextcloud 里的那一份会一起出问题。HomeVault 用 [restic](https://restic.net/) 每晚把数据**加密**备份到另一块硬盘（或云存储），出事时可以找回单个文件，也可以把整台服务器恢复到某一天的状态。

本文讲清楚：备份了什么、怎么设置、怎么检查、怎么恢复，以及怎样定期演练。

相关文档：[docs/01-架构与安全.md](01-架构与安全.md)（备份加密与威胁模型） · [docs/02-Linux部署.md](02-Linux部署.md) · [docs/03-Windows部署.md](03-Windows部署.md) · [docs/08-日常运维与升级.md](08-日常运维与升级.md) · [docs/09-常见问题.md](09-常见问题.md) · [docs/10-安卓管理App与管理面板.md](10-安卓管理App与管理面板.md)

> 命令写法：
> - **Linux**：在 HomeVault 目录下执行 `sudo ./hv <命令>`。
> - **Windows**：在 HomeVault 目录下，用**管理员身份**打开 PowerShell，执行 `.\windows\hv.ps1 <命令>`；常用操作也可以双击桌面上的"**HomeVault 管理**"，在数字菜单里选（`8` 立即备份，`9` 备份记录）。
>
> 下文一般只写 Linux 形式，Windows 把 `sudo ./hv` 换成 `.\windows\hv.ps1` 即可。两个平台不同的地方会单独写出来。

## 0. 一分钟看懂

- **每晚自动备份**：默认 03:30（`HV_BACKUP_TIME`），用 restic 加密、增量备份到**另一块物理硬盘**（或 S3 兼容的云存储）。
- **保留约一年的历史**：最近 7 天每天一份、最近 4 周每周一份、最近 12 个月每月一份。
- **每周自动抽查**：每周日的备份结束后，随机读出 5% 的备份数据，确认能正常解密。
- **restic 密码只显示一次**：安装结束时显示，请**抄在纸上离线保存**。密码丢了，备份就永远打不开。
- **找回文件的顺序**：误删 → 先看 Nextcloud 的**回收站**；改坏了 → 看**历史版本**；更早的、或回收站已清空 → 从 restic 备份里 `restore --files`；整台服务器坏了 → `restore --full`。
- **每季度演练一次恢复**。没演练过的备份，不能算真正的备份。

## 1. 3-2-1 原则：至少三份、两种介质、一份在异地

| 要求 | 含义 | 在 HomeVault 里对应什么 |
|---|---|---|
| **3** 份数据 | 原始数据 + 至少两份备份 | ① Nextcloud 数据盘上的主数据；② 本地备份盘上的 restic 仓库；③ 异地的一份 |
| **2** 种介质 | 备份不能和原件放在同一块硬盘上 | 备份盘必须是**另一块物理硬盘**。同一块硬盘上的另一个分区、另一个盘符**不算** |
| **1** 份异地 | 火灾、水灾、被盗时家里的东西可能一起没了 | 云存储（阿里云 OSS、腾讯云 COS 等），或者一块轮换放到亲戚家/办公室的移动硬盘，见 [§9](#9-异地备份) |

你可以按下面三个档次来做：

| 档次 | 做法 | 能防住什么 |
|---|---|---|
| 最低 | 主数据盘 + 本地备份盘（安装时就配好了） | 单块硬盘损坏、误删、文件被改坏 |
| **推荐** | 再加两块移动硬盘轮换，一块接在服务器上，另一块放在别处 | 以上 + 火灾被盗 + 勒索病毒（离线的那块碰不到） |
| 更好 | 本地备份盘 + 云存储 | 以上 + 不用手动换盘 |

⚠️ **手机里的原图不能算一份备份。** 手机会丢、会坏，你也迟早会为了腾空间删掉手机上的照片。

说明：HomeVault 的自动备份**一次只写一个目标**（`.env` 的 `HV_BACKUP_TARGET`：`local` 本地硬盘，或 `s3` 云存储）。要同时有本地和异地两份，请用 [§9](#9-异地备份) 里的方法。

## 2. 备份了什么、没备份什么

每次备份生成一个**快照**（snapshot），里面的路径都以 `/src/` 开头。恢复时会用到这些路径：

| 内容 | 快照里的路径 | 说明 |
|---|---|---|
| 所有人的文件 | `/src/nextcloud-data` | 包括每个人的**回收站**（`files_trashbin`）和**历史版本**（`files_versions`） |
| 数据库导出 | `/src/dumps/nextcloud.sql` | 账户、分享、通讯录、日历、标签、评论、两步验证设置、应用密码等，都在数据库里 |
| Nextcloud 配置 | `/src/nextcloud-html/config` | `config.php` 里有实例 ID 和加密用的 `secret`，恢复时**必须**和数据库、数据目录一起用 |
| 额外安装的应用、主题 | `/src/nextcloud-html/custom_apps`、`/src/nextcloud-html/themes` | |
| Caddy 数据 | `/src/caddy-data` | HTTPS 证书，以及 **IP 模式本地 CA 的根私钥** |
| HomeVault 目录 | `/src/project` | `.env`、`secrets/`（**所有密码**，包括 DNS/云存储的 API 密钥）、`storage.conf`、`state/`、`clients/` |
| VPN（Linux） | `/src/wg-easy` | wg-easy 的服务器密钥和设备列表（启用 VPN 时） |
| VPN（Windows） | `/src/windows-wireguard` | `C:\ProgramData\HomeVault\wireguard\` 里的服务器密钥 `server.key` 和设备列表 `peers.json` |
| 额外存储 | `/src/storage/<代号>` | **只有** `storage.conf` 里"是否备份"为 `yes` 的存储。代号是 `s` 开头的 9 位字符（例如 `sea173462`），`storage list` 能看到 |

**没有备份**的内容：

- **缩略图**（`appdata_*/preview`）：可以重新生成，排除掉能省下很多空间；
- Nextcloud 数据目录里的 `*.log` 日志文件，以及 HomeVault 的日志目录 `HV_LOG_DIR`（日志只保留几天，没必要备份）；
- Nextcloud 程序本身（来自 Docker 镜像，恢复时重新下载）；
- PostgreSQL 的原始数据文件（用上面的数据库导出代替）、Redis 缓存；
- 额外存储里"是否备份"为 `no` 的（例如可以重新下载的影视资料）；
- HomeVault 目录下的 `.git`、`restore/`（恢复出来的临时文件）；
- 操作系统、Docker 本身和 Docker Desktop 的设置；
- **还没有上传到服务器的手机照片**。

⚠️ 备份里有**全部密码**和本地 CA 的根私钥。restic 仓库是加密的，没有 restic 密码谁也读不出来；但**拿到仓库 + restic 密码的人，就能读出你的全部数据**。所以 restic 密码要像银行卡密码一样保管（见 [§4.3](#43-restic-密码只显示一次抄下来离线保存)）。

## 3. 备份时发生了什么（以及一个取舍）

每次备份（定时任务、`backup` 命令、管理面板的"立即备份"，都是同一个流程）：

1. 检查备份仓库能否打开（备份盘是否已接上、密码是否正确）；
2. **开启 Nextcloud 维护模式**；
3. 导出数据库（`pg_dump`）到 `HV_DUMP_DIR/nextcloud.sql`，先写临时文件，检查完整后再改名；
4. **关闭维护模式**。无论导出成功还是失败，这一步**都会执行**；
5. restic 加密备份上一节列出的所有内容（只上传有变化的部分）；
6. 按保留策略删除过期快照，并回收空间（`forget --prune`）；
7. 如果是星期日，或者加了 `--check`：随机读出 5% 的备份数据进行校验；
8. 写入状态文件（`state/last-backup-ok`、`state/backup-status.json`、`state/snapshots.json`），管理面板和 `doctor` 读取它们。

**取舍：维护模式只在导出数据库时开启。** 数据库导出通常只要几秒到几分钟，而备份几百 GB 的文件可能要几个小时。如果整个备份期间都开着维护模式，这几个小时里手机全都无法上传。所以 HomeVault 选择：

- 维护模式期间，手机 App 会暂时提示服务器正在维护，自动上传会在稍后自动重试，**不会丢照片**；
- 文件是在服务**正常运行**时备份的。如果备份进行中恰好有人上传或删除文件，快照里的文件和数据库记录可能有一点点不一致（例如多一个数据库里没有记录的新文件）；
- 这种不一致在恢复时会被自动修正：整机恢复的最后一步会执行 `occ maintenance:data-fingerprint`（通知所有客户端重新核对）和 `occ files:scan --all`（按实际文件重建文件索引）；
- 默认备份时间 03:30 正好在大家睡觉、手机充电的时候，这时一般很少有新文件。

## 4. 第一次设置

### 4.1 选择备份位置

- **必须是另一块物理硬盘。** 安装程序会检查（Linux 的 `storage list` 和管理面板"存储"页也会）：备份目标和主数据在同一块物理磁盘上时，会给出严重警告。
- 内置硬盘或 USB 移动硬盘都可以。移动硬盘建议选 USB 3.0 以上、自带电源的机械硬盘。
- 容量：至少是当前数据量的 **1.5 倍**。照片和视频基本不能压缩，而且被删除的文件会在旧快照里保留约一年。
- 文件系统：Linux 用 ext4 或 btrfs；Windows 用 NTFS。不要用 FAT32。
- **仓库放在挂载点下面的子目录里**，例如 `/mnt/backup/homevault-restic`（Linux）或 `E:\HomeVault-Backup\restic`（Windows，安装程序的默认值）。这样移动硬盘没接上时，备份会直接报错"备份目录不存在（硬盘是否已挂载？）"，而不会把备份偷偷写到系统盘上。
- Linux 上按 UUID 挂载并加 `nofail`（见 [docs/02-Linux部署.md](02-Linux部署.md) §4.4）。想更保险，可以在 `.env` 里加一行 `HV_BACKUP_REQUIRE_MOUNT=/mnt/backup`：挂载点没有挂上硬盘时，备份会拒绝运行。
- Windows 上请在"磁盘管理"里给备份盘分配一个固定的盘符。

### 4.2 初始化备份仓库

安装时选好了备份位置的，**安装程序已经初始化了仓库**，也已经设置了每晚的定时备份，可以跳到 [§4.3](#43-restic-密码只显示一次抄下来离线保存)。

安装时跳过了备份的，以后这样补上：

1. 编辑 `.env`：

   ```ini
   HV_BACKUP_TARGET=local
   HV_BACKUP_LOCAL_PATH=/mnt/backup/homevault-restic
   # Windows 例如：HV_BACKUP_LOCAL_PATH=E:/HomeVault-Backup/restic
   ```

2. 初始化并做第一次备份：

   ```bash
   sudo ./hv backup --init
   ```

   `--init` 只在仓库还不存在时才初始化，已存在的仓库不会被覆盖，多加一次也没关系。

3. 设置定时备份（见 [§5](#5-定时备份)）。

备份到云存储（S3）的设置方法见 [§9.3](#93-直接备份到云存储s3)。

### 4.3 restic 密码：只显示一次，抄下来离线保存

restic 密码是一串 32 位的随机字母和数字，保存在 HomeVault 目录的 `secrets/restic_password` 里。安装结束时的总结里会显示**一次**，类似这样：

```
restic 备份密码（只显示这一次，请抄在纸上离线保存！丢失后任何备份都无法恢复）：
  （32 位字母和数字）
```

**为什么要离线保存？** 你最需要这个密码的时候，恰恰是服务器坏掉的时候。那时 `secrets/` 目录已经读不到了，备份里虽然也有一份密码，但要先有密码才能打开备份。

建议：

- **抄在纸上**，核对两遍（注意区分 `0/O`、`1/l/I`），和房产证等重要证件放在一起；
- 或者存进你信任的**密码管理器**（和手机、电脑、服务器都无关的那种）；
- **不要**只存在这台服务器上，**不要**拍照存在会自动备份到 HomeVault 的手机相册里（服务器坏了照片也就拿不到了）。

安装时没来得及抄？只要服务器还正常，现在就可以再看一次，然后立刻抄下来：

```bash
sudo cat secrets/restic_password
```

```powershell
# Windows（管理员 PowerShell，在 HomeVault 目录下）
Get-Content .\secrets\restic_password
```

⚠️ **不要修改或删除 `secrets/restic_password`。** 已有的仓库只认初始化时的密码。改了这个文件，下一次备份就会报"仓库密码错误"。

### 4.4 第一次完整备份

安装后建议马上手动做一次完整备份，不要等到半夜：

```bash
sudo ./hv backup
```

- 第一次要把全部数据都加密写一遍，1 TB 照片写到 USB 3.0 移动硬盘，通常需要几个小时。可以在管理面板的"备份"页看状态和结果；
- 之后每晚只备份新增和修改的部分，一般几分钟就能完成；
- 备份期间 Nextcloud 可以正常使用（只有导出数据库的那一小会儿处于维护模式）。

## 5. 定时备份

### Linux：systemd 定时器

安装程序已经自动设置好了。查看、修改时间、关闭：

```bash
systemctl list-timers homevault-backup.timer    # 下一次运行时间
sudo ./hv schedule-backup --time 04:00          # 改成每天 04:00（同时写入 .env 的 HV_BACKUP_TIME）
sudo ./hv schedule-backup --remove              # 关闭定时备份
```

- 定时器设置了 `Persistent=true`：备份时间点主机正好关着的话，下次开机后会**补做一次**；
- 查看定时备份的运行记录：`journalctl -u homevault-backup.service -n 50`。

### Windows：任务计划程序

```powershell
.\windows\hv.ps1 schedule-backup                # 使用 .env 的 HV_BACKUP_TIME（默认 03:30）
.\windows\hv.ps1 schedule-backup --time 04:00   # 或指定时间
.\windows\hv.ps1 schedule-backup --remove       # 关闭定时备份
```

- 这会创建计划任务 `HomeVault-Backup`，以**已登录的 HomeVault 账户**身份运行。因为 Docker Desktop 必须有人登录才会运行，所以请按 [docs/03-Windows部署.md](03-Windows部署.md) §7 配好"自动登录 + 立即锁屏"，并且**不要注销**这个账户；
- 任务设置了"错过时尽快运行"：备份时间点电脑正好关机或睡眠的话，开机后会补做；
- 电脑在备份时间点**睡眠**了，备份就不会按时运行。请按 [docs/03-Windows部署.md](03-Windows部署.md) §8 关闭睡眠。

### 备份日志

每次备份都会生成一个日志文件：

| 平台 | 位置 |
|---|---|
| Linux | `HV_LOG_DIR/backup/backup-年月日-时分秒.log`，默认在 `/srv/homevault/logs/backup/` |
| Windows | `<数据盘>:\HomeVault\logs\backup\`，可以直接在资源管理器里打开 |

也可以在管理面板的"**备份**"页点"**查看备份日志**"，或者在"**日志**"页的"备份日志"分类里查看。日志和其他日志一样，默认保留 7 天（位置和修改方法见 [docs/08-日常运维与升级.md](08-日常运维与升级.md) §7）。

## 6. 保留策略：7 / 4 / 12

默认设置（`.env`）：

```ini
HV_BACKUP_KEEP_DAILY=7      # 最近 7 天，每天保留一份
HV_BACKUP_KEEP_WEEKLY=4     # 最近 4 周，每周保留一份
HV_BACKUP_KEEP_MONTHLY=12   # 最近 12 个月，每月保留一份
```

举个例子，今天是 9 月 26 日，你能找回的是：9 月 20–26 日每天的状态、最近 4 周每周末的状态、最近 12 个月每月月底的状态。总共大约 20 个快照，**最远能回到大约一年前**。

- 每次备份结束时都会按这个策略删除过期的快照并回收空间；
- 修改后**下一次备份**时生效；
- restic 会去重：没有变化的照片在所有快照里只存一份，所以保留很多快照并不会占用很多倍的空间。真正占空间的是**被删除和被修改的文件**：它们会在旧快照里一直保留，直到这些快照过期；
- 备份盘快满了：可以把 `HV_BACKUP_KEEP_MONTHLY` 改小（例如 6），下一次备份后空间会被回收；长远来看还是应该换一块更大的备份盘（见 [docs/08-日常运维与升级.md](08-日常运维与升级.md) §6.3）。

## 7. 校验：确认备份真的能读出来

硬盘会悄悄坏掉（坏道、位翻转），备份写进去了不代表以后能读出来。HomeVault 做了这几件事：

| 检查 | 什么时候 | 怎么看结果 |
|---|---|---|
| 随机读出 5% 的备份数据并校验（`check --read-data-subset=5%`） | **每周日**的备份结束后自动执行；手动运行 `sudo ./hv backup --check` 也会执行 | 失败时备份以失败结束，日志里有"仓库校验失败" |
| 上次成功备份的时间 | `sudo ./hv doctor` 每次都检查 | 超过 48 小时显示 ✘ |
| 备份状态 | 管理面板"概览"和"备份"页 | 备份超过 48 小时或失败时显示警告 |

**全量校验**（把整个仓库读一遍，最彻底，但很慢：2 TB 的 USB 硬盘可能要 6 小时以上）。本地备份盘建议每季度做一次，可以在演练时顺便做（Linux）：

```bash
sudo ./hv compose --profile tools run --rm backup -r /repo check --read-data
```

> 这是直接调用 restic 的高级用法：`-r /repo` 表示本地备份盘上的仓库。云存储的仓库不建议全量校验（会产生大量下载流量费用）。

**校验失败怎么办？**

1. 不要慌，也**不要**删除仓库；
2. 马上再运行一次 `sudo ./hv backup --check`，看是不是偶发问题（例如 USB 接触不良）；
3. 检查备份盘的健康状况（SMART，见 [docs/08-日常运维与升级.md](08-日常运维与升级.md) §5）；
4. 仍然失败：换一块新的备份盘，按 [docs/08-日常运维与升级.md](08-日常运维与升级.md) §6.3 建立新仓库。旧盘先别格式化，里面没有损坏的快照可能还能用。

## 8. 从备份恢复

### 8.1 先判断用哪种方法

| 情况 | 用什么 | 见 |
|---|---|---|
| 刚误删了文件（30 天内） | Nextcloud **回收站** | [§8.2](#82-回收站和历史版本不是备份但最快) |
| 文件被改坏、被覆盖了 | Nextcloud **历史版本** | [§8.2](#82-回收站和历史版本不是备份但最快) |
| 回收站里已经没有了；想要很久以前的样子；整个文件夹没了 | restic **恢复文件**（`restore --files`） | [§8.3](#83-恢复单个文件或文件夹) |
| 数据盘坏了、升级失败、被勒索病毒加密了，但这台电脑还能用 | restic **整机恢复**（`restore --full`） | [§8.4](#84-整机恢复同一台电脑) |
| 整台电脑坏了、被偷了，要在新电脑上重建 | 新电脑 + 整机恢复 | [§8.5](#85-在新电脑上灾难恢复) |
| 升级 Nextcloud 大版本后出问题 | 见 [docs/08-日常运维与升级.md](08-日常运维与升级.md) §3.3 | |

### 8.2 回收站和历史版本：不是备份，但最快

这两个功能是 Nextcloud 自带的，家人自己就能在网页上操作，不需要管理员：

- **回收站**：网页 **文件** → 左下角"**回收站**" → 找到文件 → "**恢复**"。
- **历史版本**：在文件上点右键或"…" → "**详细信息**" → "**版本**"标签 → 选一个旧版本恢复。

HomeVault 设置的保留规则（`30, auto`）：删除的文件和旧版本**至少保留 30 天**，超过 30 天后，在空间不够时会被自动清理。回收站最多占用剩余空间（设置了配额时是剩余配额）的一半，超出时最早删除的文件会先被清掉。

它们和真正的备份的区别：

| | 回收站 / 历史版本 | restic 备份 |
|---|---|---|
| 放在哪里 | 和原文件**同一块硬盘** | 另一块硬盘或云上 |
| 硬盘坏了 | 一起没了 | 还在 |
| 被勒索病毒整盘加密 | 一起被加密 | 离线/异地的那份碰不到 |
| 能回到多久以前 | 30 天左右（空间紧张时更短） | 约一年（7/4/12） |
| 谁来操作 | 每个人自己在网页上点 | 管理员在服务器上运行命令 |
| 通讯录、日历、分享设置 | 不管 | 在数据库导出里，整机恢复时一起恢复 |

### 8.3 恢复单个文件或文件夹

适用于：回收站里已经找不到的文件、很久以前的版本、整个文件夹。恢复出来的文件会放在 HomeVault 目录下的 `restore/<时间>/` 里，**不会覆盖现有的任何文件**，确认没问题后再由你放回去。

下面以"妈妈（用户名 `mama`）手机 2024 年的照片文件夹被删了"为例。

**第 1 步：列出快照，选一个时间点。**

```bash
sudo ./hv restore
```

会列出所有快照，每行一个：`ID`（8 位）、时间、主机、标签、路径。记下你要的那一次的 ID，例如 `3f2a9c1d`。

> 不指定快照时默认用**最新**的一次。但如果文件是三天前删的，最近三晚的快照里都已经没有它了，所以要选删除**之前**的那次。

**第 2 步：在快照里找到路径。** 一层一层往下看（每次只列出一层）：

```bash
sudo ./hv restore --ls /src/nextcloud-data/mama/files --snapshot 3f2a9c1d
sudo ./hv restore --ls "/src/nextcloud-data/mama/files/手机备份/小米15-妈妈/相机" --snapshot 3f2a9c1d
```

用户文件的路径规律是 `/src/nextcloud-data/<用户名>/files/<网页上看到的路径>`。额外存储是 `/src/storage/<代号>/…`，代号可以用 `sudo ./hv restore --ls /src/storage` 列出来，和 `storage list` 显示的代号对应。

**第 3 步：恢复。**

```bash
sudo ./hv restore --files "/src/nextcloud-data/mama/files/手机备份/小米15-妈妈/相机/2024" --snapshot 3f2a9c1d
```

- 可以恢复单个文件，也可以恢复整个文件夹；
- 路径里有中文或空格时，一定要用英文双引号括起来；
- Linux 上可以省略前缀，直接写 `mama/files/手机备份/小米15-妈妈/相机/2024`；Windows 上请写完整的 `/src/…` 路径；
- 完成后会显示恢复到了哪里。文件保留了快照里的完整路径，例如：
  - Linux：`restore/20260926-101500/src/nextcloud-data/mama/files/手机备份/小米15-妈妈/相机/2024/`
  - Windows：`restore\20260926-101500\src\nextcloud-data\mama\files\手机备份\小米15-妈妈\相机\2024\`

**第 4 步：放回 Nextcloud。** 为了不覆盖现有文件，建议放到一个**新文件夹**里，再让家人在网页上自己挪到想要的位置。

Linux（先用 `grep HV_NC_DATA_PATH .env` 查看数据目录，下面假设是 `/mnt/data1/nextcloud-data`）：

```bash
sudo mkdir -p "/mnt/data1/nextcloud-data/mama/files/从备份恢复"
sudo cp -a "restore/20260926-101500/src/nextcloud-data/mama/files/手机备份/小米15-妈妈/相机/2024" \
           "/mnt/data1/nextcloud-data/mama/files/从备份恢复/"
sudo chown -R 33:33 "/mnt/data1/nextcloud-data/mama/files/从备份恢复"
sudo ./hv occ files:scan --path="/mama/files/从备份恢复"
```

Windows：用资源管理器把 `restore\20260926-101500\src\nextcloud-data\mama\files\手机备份\小米15-妈妈\相机\2024` 复制到数据目录下的 `mama\files\从备份恢复\`（数据目录默认是 `<数据盘>:\HomeVault\nextcloud-data`），然后：

```powershell
.\windows\hv.ps1 occ files:scan --path="/mama/files/从备份恢复"
```

`files:scan` 让 Nextcloud 发现这些新文件，之后网页和手机 App 里就能看到了。

> 另一个办法：把恢复出来的文件拷到电脑上，登录网页直接**上传**。文件少时这样最简单，也不用管权限。

**第 5 步：清理。** `restore/` 里的文件是**没有加密的明文**，确认放回去以后删掉：

```bash
sudo rm -rf restore/20260926-101500
```

Windows 直接在资源管理器里删除 `restore\20260926-101500` 文件夹。

### 8.4 整机恢复（同一台电脑）

适用于：Nextcloud 数据、数据库或配置坏了（数据盘损坏后换了新盘、升级出错、被勒索病毒加密），但**HomeVault 目录（`.env` 和 `secrets/`）还在**。

⚠️ 整机恢复会用快照**覆盖**：Nextcloud 配置、主数据目录（**快照之后新增的文件会被删除**）、数据库、Caddy 证书数据，以及 Linux 上的 VPN（wg-easy）配置。手机里还留着的新照片没关系，恢复后自动上传会重新上传；但只在服务器上的新文件（例如电脑上传后就删掉了本地副本的），请先用 [§8.3](#83-恢复单个文件或文件夹) 的方法或直接复制出来。

**如果是硬盘坏了、换了新盘**，先把新盘挂载到**原来的位置**（Linux 按 [docs/02-Linux部署.md](02-Linux部署.md) §4 挂载；Windows 在"磁盘管理"里分配原来的盘符），然后分两种情况：

- **只坏了 Nextcloud 文件所在的盘**（`.env` 里 `HV_NC_DATA_PATH` 所在的盘）：建好一个空的数据目录，然后直接开始恢复。

  ```bash
  grep HV_NC_DATA_PATH .env                                   # 查看数据目录，例如 /mnt/data1/nextcloud-data
  sudo install -d -o 33 -g 33 -m 0750 /mnt/data1/nextcloud-data
  ```

  Windows 在资源管理器里建好同名的空文件夹即可（例如 `D:\HomeVault\nextcloud-data`）。

- **Linux 上 HomeVault 数据目录（`HV_DATA_DIR`，里面有数据库和 Nextcloud 程序）所在的盘也坏了**：先重新运行一次安装，让它重建目录并启动一个空的 Nextcloud（不会重新生成密码，会沿用现有的 `.env`），再开始恢复：

  ```bash
  sudo ./hv install
  ```

**开始恢复：**

```bash
sudo ./hv restore                                  # 列出快照，选出事之前的那一次
sudo ./hv restore --full --snapshot 3f2a9c1d       # 整机恢复
```

需要确认两次：

- Linux：先回答 `y`，再输入"**确认恢复**"四个字；
- Windows：先回答 `y`，再输入 `RESTORE`（大写）。

之后它会自动完成：停止 Nextcloud/Caddy（和 wg-easy）→ 恢复数据库导出、配置、数据目录、应用、证书（和 VPN 配置）→ 删除并重建数据库、导入导出文件 → 启动全部服务 → `occ maintenance:data-fingerprint` → `occ files:scan --all`。数据多时最后一步要很久，请耐心等待。

**整机恢复不会恢复这些，需要你手动处理：**

- **额外存储**里的文件（`storage.conf` 里那些硬盘）。整机恢复不会动它们。如果那块硬盘也坏了，而且它的"是否备份"为 `yes`，用 [§8.3](#83-恢复单个文件或文件夹) 的方法恢复 `/src/storage/<代号>`，再复制回那块硬盘的原路径（Linux 上记得 `chown -R 33:33`），然后运行 `sudo ./hv occ files:scan --all`。
- **Windows 的 VPN 配置**：见 [§8.5](#85-在新电脑上灾难恢复) 第 5 步。

恢复后按 [§8.6](#86-恢复后检查清单) 检查。

### 8.5 在新电脑上灾难恢复

适用于：整台电脑坏了、被偷了，或者系统盘坏了、HomeVault 目录也没了。

**你需要准备：**

- 备份盘（或者云存储的访问密钥 AccessKey）；
- 抄在纸上的 **restic 密码**；
- 一台新电脑（Linux 或 Windows 都可以，最好和原来的系统相同）。

**思路：** 先用 restic 密码从备份里取回旧的 HomeVault 设置（`.env`、`secrets/`、`storage.conf`），再用这些设置重新安装，最后整机恢复。这样所有密码、访问地址、VPN 端口都和原来一样，**手机和电脑基本不用重新设置**。

**第 1 步：准备新电脑。**

- 按 [docs/02-Linux部署.md](02-Linux部署.md)（安装 Docker、挂载硬盘）或 [docs/03-Windows部署.md](03-Windows部署.md)（安装 Docker Desktop、WireGuard）准备好系统；
- **尽量让一切和原来一样**：新数据盘挂载到原来的位置（Linux 挂载点、Windows 盘符相同）；备份盘也挂载到原来的位置；
- **在路由器里把原来的局域网 IP 分配给新电脑**：新电脑的网卡 MAC 地址不同，要修改"DHCP 静态分配"的绑定，否则 IP 会变，所有手机都得改设置。

**第 2 步：获取 HomeVault，放回 restic 密码。**

把 HomeVault 下载（或 `git clone`）到和原来相同的位置，例如 `/opt/homevault`。然后在 HomeVault 目录下创建密码文件，填入纸上的 restic 密码：

```bash
cd /opt/homevault
sudo install -d -m 0700 secrets
sudo nano secrets/restic_password     # 输入 restic 密码，Ctrl+O 保存，Ctrl+X 退出
```

```powershell
# Windows（管理员 PowerShell，在 HomeVault 目录下）
New-Item -ItemType Directory -Force secrets | Out-Null
$pw = Read-Host '请输入 restic 密码'
[System.IO.File]::WriteAllText("$PWD\secrets\restic_password", $pw.Trim())
Remove-Variable pw
```

（Windows 上不要用记事本另存为，记事本可能自动加上 `.txt` 扩展名。）

**第 3 步：生成临时配置，从备份里取回旧设置。**

运行一次"只生成配置、不启动服务"的安装。问到备份位置时，填**备份盘上原来的仓库路径**（或云存储的地址和密钥）；其他问题按回车用默认值即可，反正马上会被旧设置覆盖。国内网络请加 `--mirror daocloud`：

```bash
sudo ./hv install --no-start
sudo ./hv restore                      # 能列出旧快照，说明密码和仓库都对了
sudo ./hv restore --files /src/project
```

```powershell
.\windows\hv.ps1 install --config-only
.\windows\hv.ps1 restore
.\windows\hv.ps1 restore --files /src/project
```

安装程序发现 `secrets/restic_password` 已经存在，**不会**生成新密码。如果 `restore` 报"仓库密码错误"，说明密码抄错了或者输错了，检查后重新编辑密码文件。

**第 4 步：把旧设置复制回来。** 假设上一步显示恢复到了 `restore/20260926-101500/`：

```bash
R=restore/20260926-101500/src/project
sudo cp -a "$R/.env" .env
sudo cp -a "$R/secrets/." secrets/
[ -f "$R/storage.conf" ] && sudo cp -a "$R/storage.conf" .
```

```powershell
$R = 'restore\20260926-101500\src\project'
Copy-Item "$R\.env" .\.env -Force
Copy-Item "$R\secrets\*" .\secrets\ -Force
if (Test-Path "$R\storage.conf") { Copy-Item "$R\storage.conf" . -Force }
```

- **只复制这三样**。不要复制 `state/` 目录（里面记录的是旧电脑的安装状态）；
- 打开 `.env` 看一眼路径是否和新电脑一致：`HV_NC_DATA_PATH`、`HV_DATA_DIR`（Linux）、`HV_BACKUP_LOCAL_PATH`、`HV_LOG_DIR`。盘符或挂载点不同的，改成新的；
- 新电脑的局域网 IP 和原来不同的（最好别这样，见第 1 步），Linux 上要把 `.env` 里的 `HV_LAN_IP` 和 `HV_BIND_IP` **都**改成新 IP；
- `storage.conf` 里的额外存储硬盘如果没有了，先把对应的行删掉（行首加 `#`）。

**第 5 步（仅 Windows，启用了 VPN 时）：放回 VPN 服务器密钥。** 这样手机上原来的 VPN 配置可以继续用：

```powershell
.\windows\hv.ps1 restore --files /src/windows-wireguard
New-Item -ItemType Directory -Force C:\ProgramData\HomeVault\wireguard | Out-Null
Copy-Item 'restore\<时间>\src\windows-wireguard\server.key','restore\<时间>\src\windows-wireguard\peers.json' C:\ProgramData\HomeVault\wireguard\ -Force
```

（把 `<时间>` 换成这次恢复显示的文件夹名。）Linux 的 VPN 配置在整机恢复时会自动恢复，不需要这一步。

**第 6 步：正式安装。** 这次安装会沿用旧的设置和密码，问题的默认值就是原来的值，核对一下（特别是局域网 IP）然后回车：

```bash
sudo ./hv install
```

```powershell
.\windows\hv.ps1 install
```

安装完成后，你得到的是一个**空的** Nextcloud，这是正常的。

**第 7 步：整机恢复。** 先列出快照，选**出事之前最后一次**的 ID。注意时间：新电脑安装后如果已经跑过定时备份，最新的快照是空的新系统，**不要选它**。

```bash
sudo ./hv restore
sudo ./hv restore --full --snapshot 3f2a9c1d
```

```powershell
.\windows\hv.ps1 restore
.\windows\hv.ps1 restore --full --snapshot 3f2a9c1d
```

**第 8 步：收尾。**

1. 额外存储的硬盘也坏了的，按 [§8.4](#84-整机恢复同一台电脑) 的说明从 `/src/storage/<代号>` 恢复；
2. 路由器：确认 UDP 端口转发指向新电脑（IP 没变就不用改）；
3. 删除 `restore/` 下的临时文件（里面有明文的密码文件）：Linux `sudo rm -rf restore/*`，Windows 在资源管理器里清空 `restore` 文件夹；
4. 按下一节检查；
5. 手动做一次备份：`sudo ./hv backup`。

### 8.6 恢复后检查清单

- [ ] `sudo ./hv doctor` 全部 ✔（或只有你能解释的 !）；
- [ ] 浏览器打开访问地址，用原来的账户登录，照片、文件都在；
- [ ] IP 模式：运行 `sudo ./hv ca`，显示的**根证书指纹和原来一样**（整机恢复会恢复旧的本地 CA，手机和电脑不用重新装证书）；
- [ ] 手机 Nextcloud App 能正常刷新，自动上传继续工作。App 可能提示文件冲突，按提示处理即可；
- [ ] 通讯录、日历（DAVx⁵）能同步；
- [ ] VPN：在外面用 4G 连一次；
- [ ] 管理面板"备份"页显示最近一次备份成功。

**如果网页显示"需要更新"，或者恢复最后一步报错：** 说明备份时的 Nextcloud 版本比现在运行的版本旧（例如恢复了升级之前的快照）。运行下面的命令完成数据库升级，再手动补做最后两步：

```bash
sudo ./hv occ upgrade
sudo ./hv occ maintenance:mode --off
sudo ./hv occ maintenance:data-fingerprint
sudo ./hv occ files:scan --all
```

## 9. 异地备份

### 9.1 三种做法

| 做法 | 优点 | 缺点 |
|---|---|---|
| **A. 两块移动硬盘轮换**（推荐） | 不花月费；不在身边的那块完全离线，勒索病毒和雷击都碰不到；恢复快 | 要记得定期去换 |
| **B. 本地备份 + 定期复制到云** | 本地恢复快，云上还有一份 | 需要自己配置 rclone 等工具 |
| **C. 直接备份到云存储**（`HV_BACKUP_TARGET=s3`） | 全自动，不用换盘 | 家里只剩主数据一份；第一次上传很慢；有存储费和流量费；恢复要从云上下载 |

### 9.2 做法 A：两块移动硬盘轮换

1. 准备两块容量相同的移动硬盘，分别叫 A 盘、B 盘；
2. **挂载到同一个位置**：
   - Linux：两块盘格式化时用同一个卷标，例如 `sudo mkfs.ext4 -L hvbackup /dev/sdX1`，fstab 里写 `LABEL=hvbackup /mnt/backup ext4 defaults,nofail 0 2`，哪块接上就挂哪块；
   - Windows：在"磁盘管理"里给两块盘分配**同一个盘符**（每次只接一块）；
3. 第一次接上某块盘时，运行一次 `sudo ./hv backup --init`，在这块盘上建立仓库。两块盘上的仓库用的是同一个 restic 密码；
4. 以后每隔一到两周换一次：接上另一块，拔下的那块带到办公室、父母家等**不在同一栋房子里**的地方；
5. 换盘后马上手动做一次备份，确认成功。

### 9.3 直接备份到云存储（S3）

restic 支持所有 S3 兼容的对象存储，国内常用阿里云 OSS 和腾讯云 COS。备份在你的电脑上就加密好了，**云服务商只能看到加密后的数据块**。

**准备：**

1. 在云控制台创建一个**私有**存储桶，存储类型选"**标准**"或"**低频访问**"。**不要**选"归档""冷归档""深度冷归档"：restic 需要随时读取数据；
2. **不要**给这个存储桶设置"生命周期规则"（自动删除或自动转成归档），它会破坏 restic 仓库；
3. 创建一个**专用的子账号**（阿里云 RAM 用户 / 腾讯云子用户），只给它**这一个存储桶**的读写权限，为它生成 AccessKey。不要用主账号的密钥。

**配置：** 最简单的方法是（重新）运行一次安装，在"备份"这一步选择 `s3`，按提示填写仓库地址、附加选项和 AccessKey，安装程序会替你写好 `.env` 和密钥文件。也可以手动编辑 `.env`：

```ini
HV_BACKUP_TARGET=s3
# 阿里云 OSS（杭州）示例：
HV_BACKUP_S3_REPO=s3:https://oss-cn-hangzhou.aliyuncs.com/你的桶名/homevault
HV_BACKUP_S3_OPTIONS='-o s3.bucket-lookup=dns -o s3.region=oss-cn-hangzhou'
```

```ini
# 腾讯云 COS（广州）示例：桶名带 APPID，形如 homevault-1250000000
HV_BACKUP_S3_REPO=s3:https://cos.ap-guangzhou.myqcloud.com/你的桶名-APPID/homevault
HV_BACKUP_S3_OPTIONS='-o s3.bucket-lookup=dns -o s3.region=ap-guangzhou'
```

手动配置时，还要创建密钥文件 `secrets/backup.env`（只有管理员能读），内容为两行：

```ini
AWS_ACCESS_KEY_ID=你的AccessKeyId
AWS_SECRET_ACCESS_KEY=你的AccessKeySecret
```

Linux 上创建后执行 `sudo chmod 600 secrets/backup.env`。最后初始化并做第一次备份：`sudo ./hv backup --init`。

Linux 也可以在安装时用参数一次配好：`--backup-target s3 --s3-repo <仓库地址> --s3-options "<选项>" --s3-key-id <ID> --s3-secret-file <存放密钥的文件>`。

**注意事项：**

- **阿里云 OSS 新账号的限制**：据阿里云帮助中心的公告摘要（原文页面未能直接打开核实），**2025 年 3 月 20 日及以后**开通 OSS 的账号，访问中国内地地域的存储桶时，通过默认的公网域名做数据读写会被拒绝（错误 `PublicEndpointForbidden`），需要绑定自定义域名（内地地域通常还要求域名已备案）。香港地域（`oss-cn-hongkong`）据称不受此限制。遇到这个错误时，请以阿里云控制台的最新说明为准。
- **腾讯云 COS**：2024 年 1 月 1 日以后创建的存储桶不支持"路径方式"访问，所以 `-o s3.bucket-lookup=dns` **必须**加上。
- 以上 OSS 的写法来自 restic 官方文档；COS 的写法按 S3 兼容规则推导，HomeVault 没有在真实账号上测试过。第一次备份完成后，请务必用 `sudo ./hv restore --ls /src/project` 试着读一次。
- **上传速度**：家庭宽带的上行通常只有 30–100 Mbps，1 TB 数据第一次上传可能要好几天，这期间备份会一直在运行，请保持开机。万一中断了也不要紧，再次备份时已经上传的数据大多不用重传。
- **费用**：按存储容量、请求次数、下载流量计费。平时只有少量下载；**整机恢复时要把全部数据下载回来**，会产生一笔外网流出流量费。开通前请在控制台看清价格。

### 9.4 做法 B：本地备份再复制到云

如果你熟悉 [rclone](https://rclone.org/)，可以保持本地备份（`HV_BACKUP_TARGET=local`），另外每天在备份**完成之后**（例如早上 7 点）用 rclone 把整个仓库目录同步到云上，例如 `rclone sync /mnt/backup/homevault-restic oss:你的桶名/homevault-restic`。restic 仓库就是一堆加密文件，复制过去的仓库可以直接用 restic 打开。注意：**不要**在备份正在运行时同步，以免复制到写了一半的状态。rclone 不是 HomeVault 的一部分，这里不展开。

## 10. 防勒索病毒

勒索病毒会把它能碰到的文件全部加密，然后要钱。对 HomeVault 来说：

- **电脑中毒**：如果这台电脑装了 Nextcloud 桌面客户端，被加密的文件会**同步到服务器**，覆盖好的版本。不要慌：历史版本（30 天）和 restic 快照（约一年）里还有中毒之前的样子。先让所有电脑断网、停止同步，查杀病毒后，再用整机恢复或恢复文件回到中毒之前。
- **服务器本身中毒**：攻击者拿到服务器的 root/管理员权限后，可以删除一直接在服务器上的备份盘里的仓库。能防住这种情况的只有**离线**和**异地**的那份：轮换下来放在别处的移动硬盘，或者云上的仓库（可以在存储桶上开启"版本控制"，被删除或覆盖的对象仍能找回，但会增加存储费用）。
- **不要**把备份目录添加为 Nextcloud 的额外存储，**不要**把备份盘共享到局域网；
- Windows 服务器上的备份盘有盘符，自动登录的那个账户能读写它。更要做好离线轮换的那一份；
- 经常看一眼管理面板"备份"页里每次的"**新增数据**"。平时每晚只新增几十 MB 到几 GB，如果某天突然新增了几百 GB，而没有人上传大量文件，就要警惕是不是有东西被批量加密了；
- restic 密码抄在纸上：服务器被攻破时，你依然能在另一台电脑上打开备份。

## 11. 管理面板和手机 App 里的"备份"页

浏览器打开管理面板 `https://<访问地址>:9443`（用 Nextcloud 管理员账户登录），或者在安卓 App"HomeVault 家庭归档"里，点"**备份**"：

- **备份状态**：上次成功、上次运行、耗时、备份目标、每日计划、下次运行、新增数据（新文件数、修改文件数）；
- **立即备份**：点按钮 → 确认 → 面板把一个"备份请求"交给服务器，服务器会在约 2 分钟内开始执行（Linux 通常几秒内开始；Windows 由每 2 分钟运行一次的计划任务 `HomeVault-Requests` 执行）。下面的"备份请求"列表会显示"等待主机执行 → 执行中 → 成功/失败"；
- **查看备份日志**：直接打开这次备份的日志；
- **备份快照**：最近的快照列表（时间、ID、处理了多少数据、新增多少）；
- 顶部的警告：超过 48 小时没有成功备份、备份失败时会在这里和"概览"页显示。

为了安全，**面板和 App 里不能恢复文件**，也不能删除快照。恢复只能由管理员在服务器上用命令完成（本文 [§8](#8-从备份恢复)）。管理面板和 App 的完整介绍见 [docs/10-安卓管理App与管理面板.md](10-安卓管理App与管理面板.md)。

Windows 上也可以用"HomeVault 管理"菜单：`8` 立即备份，`9` 备份记录（列出快照）。

## 12. 定期恢复演练

### 每月：恢复一个文件（5 分钟）

1. 在网页上随便挑一张一个月以前的照片，记下它的路径；
2. `sudo ./hv restore --files "/src/nextcloud-data/<用户名>/files/<路径>"`；
3. 打开 `restore/<时间>/` 下恢复出来的文件，确认能正常查看；
4. 删除 `restore/<时间>/`。

### 每季度：完整演练（半天）

能在另一台电脑或虚拟机上完整走一遍 [§8.5](#85-在新电脑上灾难恢复)，才能真正放心。演练时请注意这几点，**别让演练影响正式的服务器**：

- [ ] 核对纸上的 restic 密码还在、字迹清楚，并且**就是用它**完成的演练（不要从服务器上复制）；
- [ ] 最好先把备份仓库**复制一份**给演练机用（例如复制到另一块硬盘）。直接用正式的备份盘也可以，但要做到下面几条；
- [ ] 演练机安装时**不要设置定时备份**：Linux 用 `sudo ./hv install --no-systemd`；Windows 在安装程序问"创建每日备份计划任务"时回答 `n`。演练期间**不要**运行 `backup` 和 `update`，也**不要**在演练机的管理面板里点"立即备份"（Windows 演练机上的 `HomeVault-Requests` 任务会照样执行它）。否则演练机会往正式仓库里写快照，并按保留策略清理掉正式服务器的快照；
- [ ] 演练机和正式服务器在同一个局域网时，要用**演练机自己的 IP**：Linux 在取回的 `.env` 里把 `HV_LAN_IP` 和 `HV_BIND_IP` 都改成演练机的 IP，Windows 在安装时把局域网 IP 改成演练机的；
- [ ] 取回的旧 `.env` 里如果启用了 DDNS（`HV_DDNS_ENABLED=true`），在演练机上先改成 `false`，否则演练机会去修改你的域名解析；
- [ ] 顺便做一次全量校验（[§7](#7-校验确认备份真的能读出来)）；
- [ ] 记下花了多长时间、遇到了什么问题；
- [ ] 演练结束后关闭并删除演练环境（Linux：`sudo ./hv compose down -v`），删除演练机上的 `restore/` 和 `secrets/`。

## 13. 命令速查

| 操作 | Linux | Windows |
|---|---|---|
| 立即备份 | `sudo ./hv backup` | `.\windows\hv.ps1 backup`，或菜单 `8` |
| 初始化仓库并备份 | `sudo ./hv backup --init` | `.\windows\hv.ps1 backup --init` |
| 备份并抽查 5% | `sudo ./hv backup --check` | `.\windows\hv.ps1 backup --check` |
| 列出快照 | `sudo ./hv restore` 或 `sudo ./hv backup --list` | `.\windows\hv.ps1 restore` 或 `.\windows\hv.ps1 backup --list`，或菜单 `9` |
| 浏览快照内容 | `sudo ./hv restore --ls <路径> [--snapshot ID]` | `.\windows\hv.ps1 restore --ls <路径> [--snapshot ID]` |
| 恢复文件到 `restore/<时间>/` | `sudo ./hv restore --files <路径> [--snapshot ID]` | `.\windows\hv.ps1 restore --files <路径> [--snapshot ID]` |
| 整机恢复 | `sudo ./hv restore --full [--snapshot ID]` | `.\windows\hv.ps1 restore --full [--snapshot ID]` |
| 设置/修改定时备份 | `sudo ./hv schedule-backup [--time HH:MM]` | `.\windows\hv.ps1 schedule-backup [--time HH:MM]` |
| 关闭定时备份 | `sudo ./hv schedule-backup --remove` | `.\windows\hv.ps1 schedule-backup --remove` |
| 清除残留的仓库锁 | `sudo ./hv backup --unlock` | `.\windows\hv.ps1 backup --unlock` |
| 查看 restic 密码 | `sudo cat secrets/restic_password` | `Get-Content .\secrets\restic_password` |

Linux 非交互地整机恢复（例如写在脚本里）需要同时加 `--yes --force`。

### 常见报错

| 报错 | 原因 | 处理 |
|---|---|---|
| 备份目录不存在 / 备份目录不可用（硬盘是否已挂载？） | 移动硬盘没接上、没挂载，或盘符变了 | 接上硬盘；Linux 检查 `mount`，Windows 检查盘符 |
| 备份仓库不存在或尚未初始化 | 新换的备份盘还没有仓库 | `backup --init` |
| 仓库密码错误 | `secrets/restic_password` 被改过，或者不是这个仓库的密码 | 换回原来的密码文件；新电脑上检查抄写的密码 |
| 无法锁定仓库 | 另一个备份正在运行，或者上次备份被强行中断留下了锁 | 先确认没有备份在运行（管理面板"备份"页不是"执行中"），再运行 `sudo ./hv backup --unlock` |
| 部分源文件无法读取，快照不完整 | 有文件在备份时读不出来（权限、坏道、额外存储硬盘没接上） | 看日志里是哪些文件；修好后重新备份 |
| 数据库容器未运行 / Nextcloud 未运行 | 服务没有启动 | `sudo ./hv up`，再备份 |
| 网页一直显示"维护模式" | 备份在导出数据库时被强行中断（例如停电） | `sudo ./hv occ maintenance:mode --off` |

更多问题见 [docs/09-常见问题.md](09-常见问题.md)"备份"一节。
