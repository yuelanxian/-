# 08 · 日常运维与升级

HomeVault 装好以后，大部分事情都会自动进行：每 5 分钟跑一次后台任务，每晚备份，每天整理和清理日志，证书自动续期。平时想看一眼服务器怎么样，用手机打开**管理面板**就行。本文告诉你**需要定期看什么、日志在哪里、怎样升级、出了状况怎么处理**。

相关文档：[docs/01-架构与安全.md](01-架构与安全.md) · [docs/02-Linux部署.md](02-Linux部署.md) · [docs/03-Windows部署.md](03-Windows部署.md) · [docs/04-VPN与DDNS.md](04-VPN与DDNS.md) · [docs/07-备份与恢复.md](07-备份与恢复.md) · [docs/09-常见问题.md](09-常见问题.md) · [docs/10-安卓管理App与管理面板.md](10-安卓管理App与管理面板.md)

> 命令写法：
> - **Linux**：在 HomeVault 目录下执行 `sudo ./hv <命令>`。
> - **Windows**：在 HomeVault 目录下，用**管理员身份**打开 PowerShell，执行 `.\windows\hv.ps1 <命令>`。
>
> 两个平台的子命令完全相同。下文只写 Linux 的形式，Windows 把 `sudo ./hv` 换成 `.\windows\hv.ps1` 即可。Windows 上常用的操作也可以双击桌面的"HomeVault 管理"，在数字菜单里完成（见 [docs/03-Windows部署.md](03-Windows部署.md) §5.6）。
>
> **管理面板：** `https://HV_HOST:9443`，用 Nextcloud 管理员账户登录，手机上也可以装"HomeVault 家庭归档"App。下文提到"面板"时都指它，用法见 [docs/10-安卓管理App与管理面板.md](10-安卓管理App与管理面板.md)。

## 1. 检查清单

### 每天（自动进行，你只需偶尔瞄一眼）

| 自动任务 | 时间 |
|---|---|
| Nextcloud 后台任务（`cron` 容器） | 每 5 分钟 |
| Nextcloud 维护类后台任务 | 维护窗口内，由 `HV_MAINTENANCE_WINDOW_UTC` 决定。默认 18（UTC 时间），即北京时间 02:00–06:00 |
| restic 备份 | 每晚 `HV_BACKUP_TIME`（默认 03:30） |
| 每日维护：导出容器日志、轮转 Nextcloud 日志、删除过期日志、更新状态文件 | 每天一次（Linux 00:10，Windows 04:00，见 [§7.4](#74-每日维护任务)） |
| 给管理面板更新状态（服务器状态、VPN 设备） | Linux 每 5 分钟；Windows 每 2 分钟 |
| 执行管理面板提交的请求（立即备份、清理日志、改保留天数） | Linux 几秒内；Windows 每 2 分钟 |
| 证书续期 | Caddy 自动完成 |

**你要做的：** 偶尔打开管理面板的**概览**页，没有问题时会显示"一切正常"，有问题会列出告警（服务停了、硬盘快满、备份太久没成功等）。偶尔也打开手机上的 Nextcloud App，看看"自动上传"有没有卡住；家人说"照片好几天没传了"，就按 [docs/05-安卓手机备份.md](05-安卓手机备份.md) 排查。

### 每周（5 分钟）

- [ ] 看一眼管理面板的**概览**页，确认没有告警
- [ ] 运行 `sudo ./hv doctor`，确认全部 ✔
- [ ] 确认"上次备份时间"在 48 小时以内（`doctor` 会检查）
- [ ] 每周日的备份会自动抽查 5% 的备份数据；如果失败，`doctor` 和备份日志里会有提示
- [ ] 看一眼剩余空间（`doctor` 会对低于 10% 的硬盘给出警告）

### 每月（15–30 分钟）

- [ ] `sudo ./hv update`：更新到当前大版本的最新补丁版（会先自动备份）
- [ ] 检查硬盘 SMART 健康状况（见 [§5](#5-硬盘健康smart)）
- [ ] **演练恢复一个文件**：`sudo ./hv restore --files <快照里的路径>`，确认能打开（见 [docs/07-备份与恢复.md](07-备份与恢复.md)）
- [ ] 使用 btrfs 的：执行一次 `sudo btrfs scrub start -B /mnt/data1`（换成你的挂载点）
- [ ] 检查用户和设备：每个人的 **个人设置 → 安全** 里有没有不认识的设备或会话；wg-easy / `vpn list` 里有没有不再使用的 VPN 客户端
- [ ] 抽空看看审计日志和登录失败记录（见 [§7](#7-日志在哪里保留多久)）
- [ ] 安卓管理 App 有新版本时更新（见 [§11](#11-管理面板与安卓管理-app)）
- [ ] Windows：确认 Windows 更新、Docker Desktop 没有卡在某个需要手动确认的界面

### 每季度到每半年

- [ ] 确认 restic 密码的**离线副本**还在、还能看清
- [ ] 有条件的话，在另一台电脑或虚拟机上做一次**整机恢复演练**（`restore --full`）
- [ ] 看看 Nextcloud 有没有新的大版本，按 [§3.3](#33-nextcloud-大版本升级34--35) 计划升级
- [ ] 检查异地备份（如果有）是否正常增长

### 每年

- [ ] 评估硬盘"年龄"和 SMART 趋势，提前更换老化的硬盘
- [ ] 检查操作系统是否仍在支持期内。例如 Windows 10 面向个人用户的扩展安全更新（ESU）于 **2026-10-13** 结束
- [ ] 清理不再使用的账户、应用密码和 VPN 客户端

## 2. 状态、日志与体检

| 命令 | 作用 |
|---|---|
| `sudo ./hv status` | 列出各服务的运行状态和健康状态 |
| `sudo ./hv logs` | 查看全部服务的容器日志（Linux 在终端里会持续跟随，Ctrl+C 退出） |
| `sudo ./hv logs app` | 只看某个服务，可用的服务名：`app`、`cron`、`db`、`redis`、`caddy`、`panel`、`socket-proxy`、`wg-easy`（Linux）、`ddns-go`、`scrutiny`、`backup` |
| `sudo ./hv logs list` / `logs show …` | 列出 / 查看日志目录里的日志文件，见 [§7](#7-日志在哪里保留多久) |
| `sudo ./hv doctor` | 逐项体检，✔ 表示正常，✘ 表示有问题并附处理建议 |
| `sudo ./hv occ status` | Nextcloud 版本、是否已安装、是否处于维护模式 |
| `sudo ./hv occ setupchecks` | Nextcloud 自带的安全和配置检查，和网页上 **管理设置 → 概览** 的内容相同 |
| `sudo ./hv harden` | 重新应用安全加固，并显示关键设置 |
| `sudo ./hv up` / `down` / `restart` | 启动 / 停止 / 重启全部服务 |

不想登录服务器时，管理面板能看到大部分同样的信息：**概览**页显示每个服务的状态和告警，可以直接重启 `app`、`caddy` 等服务；**日志**页能看日志文件和容器日志。

`doctor` 的检查项和 ✘ 的处理方法，见 [docs/02-Linux部署.md](02-Linux部署.md) §13。Windows 上还会检查隧道服务是否在运行、弱主机模式是否生效，以及自动登录和 Docker Desktop 自启动的设置（见 [docs/03-Windows部署.md](03-Windows部署.md)）。

## 3. 升级

### 3.1 HomeVault 的版本策略

- 所有镜像都**固定到版本号**，写在 `.env` 里：`NEXTCLOUD_IMAGE`、`POSTGRES_IMAGE`、`REDIS_IMAGE`、`CADDY_IMAGE`、`WG_EASY_IMAGE`、`RESTIC_IMAGE`、`DDNS_GO_IMAGE`、`SCRUTINY_IMAGE`、`SOCKET_PROXY_IMAGE`。管理面板 `PANEL_IMAGE`（`homevault/panel:<版本>`）是在本机从源码构建的，不从网上拉取。
- 例如 `nextcloud:34-apache` 表示"34 这个大版本里最新的补丁版"。所以 `update` 会拿到 34.0.x 的安全修复，但**不会**自己跳到 35。
- 永远不用 `latest`。原因之一：wg-easy 的 `latest` 标签其实还指向旧的 v14。
- 截至 2026-09 的默认版本：Nextcloud 34（stable，34.0.4）、PostgreSQL 18、Redis 8、Caddy 2.11.4、wg-easy 15、restic 0.19.1、ddns-go v6.17.7、Scrutiny v0.9.4、socket-proxy 3.4.5（`3.4.5-r0-ls99`）、管理面板 1.0.0。

### 3.2 日常更新（同一大版本内）

```bash
sudo ./hv update
```

它会依次：

1. **先做一次备份**。如果刚备份过，确定要跳过，可以加 `--skip-backup`，但不推荐；
2. 拉取新镜像；
3. 重建并启动容器；
4. 等服务恢复健康。Nextcloud 容器启动时会自动执行 `occ upgrade`，之后 HomeVault 再执行 `occ db:add-missing-indices` 等收尾工作。

更新完运行一次 `sudo ./hv doctor`。

### 3.3 Nextcloud 大版本升级（34 → 35）

**规则：一次只能升一个大版本。** Nextcloud 官方镜像会拒绝跨越多个大版本的升级，也拒绝降级，遇到这种情况容器会直接启动失败。例如从 33 升到 35，必须先 33 → 34，再 34 → 35。

**时间上不用急。** Nextcloud 每 4 个月发布一个大版本，每个大版本维护一年：

| 大版本 | 发布日期 | 支持到 |
|---|---|---|
| 35 | 2026-09-16 | 2027-09 |
| 34（HomeVault 当前默认） | 2026-06-09 | 2027-06 |
| 33 | 2026-02-18 | 2027-02 |

建议等新大版本出了几个补丁版、你常用的应用都兼容以后，再升级。

**步骤：**

1. **先把当前版本更新到最新补丁版**，并确认一切正常：

   ```bash
   sudo ./hv update
   sudo ./hv doctor
   ```

2. **检查应用兼容性。** 用管理员登录网页，到 **应用** 页面，看你额外安装的第三方应用是否支持新版本。

3. **提前通知家人**：升级期间（通常几分钟到半小时）无法访问，手机会在恢复后自动继续上传。

4. **执行大版本升级：**

   ```bash
   sudo ./hv update --major
   ```

   它会把 `.env` 里的 `NEXTCLOUD_IMAGE` 大版本号**加 1**（例如 `34-apache` → `35-apache`），然后照常执行"先备份 → 拉取 → 启动 → 升级数据库"。

5. **观察升级过程：**

   ```bash
   sudo ./hv logs app
   ```

   日志里出现升级完成、Apache 启动的信息即可。数据量大时，第一次启动会比较慢，请耐心等待，**不要中途重启**。

6. **检查：**

   ```bash
   sudo ./hv doctor
   sudo ./hv occ status
   sudo ./hv occ setupchecks
   ```

   然后用手机拍一张照片，确认能自动上传。

**万一升级失败怎么回退？** Nextcloud 不支持降级，不能直接把镜像改回 34。正确做法是：

1. 把 `.env` 里的 `NEXTCLOUD_IMAGE` 改回原来的版本（例如 `docker.io/library/nextcloud:34-apache`，或你设置的镜像前缀）；
2. 用升级前那次备份做整机恢复：`sudo ./hv restore --full --snapshot <升级前的快照ID>`（见 [docs/07-备份与恢复.md](07-备份与恢复.md)）。

⚠️ 这会丢掉那次备份之后新上传的数据。手机上的文件通常还在，恢复后会重新上传。

### 3.4 其他组件

- **PostgreSQL 大版本**（例如 18 → 19）**不能**直接换镜像号，需要导出再导入数据。HomeVault 固定在 18，请不要自己改 `POSTGRES_IMAGE` 的大版本号。
- **Caddy、Redis、restic、wg-easy、ddns-go** 的版本随 HomeVault 套件一起调整。

### 3.5 升级 HomeVault 套件本身

```bash
cd /opt/homevault
sudo git pull
# 阅读更新说明（如有），然后：
sudo ./hv install     # 重新运行是安全的：不会重新生成密码，会复用现有的 .env 和 secrets/
sudo ./hv doctor
```

只改了脚本或配置时，也可以直接 `sudo ./hv up`：它会重新计算派生设置，并按需重建容器。

**管理面板**的镜像是在本机从 `panel/` 目录构建的，不会被 `update` 或 `pull` 从网上拉取。Linux 上 `install`、`up`、`update` 会自动发现 `panel/` 源码有变化并重新构建；想手动强制重建：

```bash
sudo ./hv compose build panel
sudo ./hv up
```

**Windows：** 用新版本覆盖 HomeVault 目录（保留 `.env`、`secrets\`、`storage.conf`、`state\`、`clients\` 这些你自己的文件），然后重新双击 `一键安装.cmd`。它不会重新生成密码，并会重新构建管理面板镜像（`update` 也会）。最后在菜单里做一次**健康检查**。

安卓管理 App 的更新见 [§11](#11-管理面板与安卓管理-app)。

### 3.6 Windows 上的其他更新

| 软件 | 建议 |
|---|---|
| Docker Desktop | 在 Settings → Software updates 里选择合适的更新方式，每月手动检查一次。更新时 Docker 引擎会重启，容器随后自动恢复（`restart: unless-stopped`）。更新后运行 `.\windows\hv.ps1 doctor` |
| WireGuard for Windows | 自带更新检查；也可以在管理员命令行运行 `wireguard /update` |
| Windows 更新 | 允许在夜间自动重启。重启后的自动恢复流程见 [docs/03-Windows部署.md](03-Windows部署.md) |
| 计划任务 | 不需要手动维护。缺失或损坏时，重新双击 `一键安装.cmd` 即可恢复，任务列表见 [docs/03-Windows部署.md](03-Windows部署.md) §7.5 |

## 4. 证书续期

| 模式 | 证书 | 续期 | 你需要做什么 |
|---|---|---|---|
| IP 模式（`internal`） | 网站证书有效期 12 小时，中间证书 7 天 | Caddy 自动轮换 | 什么都不用做 |
| | **根证书**有效期约 10 年 | 不会自动更换 | 快到期时（安装后大约 10 年）需要生成新的根证书，并重新安装到所有设备上。`doctor` 会检查证书有效期 |
| 域名模式（`acme-dns`） | Let's Encrypt 证书，有效期较短 | Caddy 在到期前通过 DNS-01 自动续期 | 保证 DNS 服务商的 API 密钥一直有效；`doctor` 显示证书快过期时，用 `sudo ./hv logs caddy` 查看续期失败的原因 |

- 域名模式续期失败，常见原因是 API 密钥被删除、失效或权限不够，或者主机访问不了外网。修好后运行 `sudo ./hv restart`，让 Caddy 重试。
- IP 模式下需要重新导出根证书时（例如给新手机安装）：`sudo ./hv ca --export <路径>`。

## 5. 硬盘健康（SMART）

### 5.1 剩余空间

- `doctor` 会检查**每块用到的硬盘**（主数据、额外存储、备份目标、程序数据），可用空间低于 10% 时给出警告。
- 空间紧张时可以：
  1. 给家人设置配额：`sudo ./hv user add` 时加 `--quota`，或在网页的 **用户** 页面修改；
  2. 清空回收站和旧版本：Nextcloud 会按保留策略自动清理，也可以让家人手动清空回收站；
  3. 增加硬盘：见 [§6](#6-以后增加或移除硬盘)；
  4. 备份盘满了：见 [docs/07-备份与恢复.md](07-备份与恢复.md)，可以调整保留策略 `HV_BACKUP_KEEP_DAILY/WEEKLY/MONTHLY`。
- Windows：Docker Desktop 的虚拟磁盘文件只会变大、不会自动缩小。它里面放着数据库和程序文件，照片不在里面（照片在 NTFS 数据目录里）。

### 5.2 Linux：Scrutiny（可选，profile `monitor`）

HomeVault 自带一个可选的 [Scrutiny](https://github.com/AnalogJ/scrutiny) 服务（`ghcr.io/analogj/scrutiny:v0.9.4-omnibus`），它会每天收集一次硬盘 SMART 数据，并显示趋势图。

- 启用方法：编辑 `.env`，设置 `HV_MONITOR_ENABLED=true`（启用 `monitor` profile），并用 `HV_SCRUTINY_DEVICES` 列出要监控的硬盘，用空格分隔，例如 `'/dev/sda /dev/sdb'`（可以用 `sudo smartctl --scan` 查看有哪些硬盘）。然后执行 `sudo ./hv up`：它会把这些设备写进 `compose.storage.yaml` 再启动 Scrutiny；以后增减硬盘，改完 `HV_SCRUTINY_DEVICES` 再运行一次 `sudo ./hv up` 即可。写错或当前不存在的设备会被跳过并给出警告（否则 Scrutiny 容器启动不了）。网页端口由 `HV_SCRUTINY_PORT` 设置，默认 8080。
- 出于安全考虑，Scrutiny 的网页**只绑定在主机的 `127.0.0.1` 上**，因为它没有登录功能。要在别的电脑上查看，先用 SSH 端口转发：

  ```bash
  ssh -L 8080:127.0.0.1:8080 你的用户名@192.168.1.10
  # 然后在这台电脑的浏览器打开 http://localhost:8080
  ```

- Scrutiny 可以通过 Shoutrrr 格式的 URL 发通知，例如邮件（SMTP）、企业微信（`wecom://`）、Bark、ntfy 等，配置在 Scrutiny 的配置文件 `scrutiny.yaml` 的 `notify: urls:` 里。

**不想用 Scrutiny？** 可以直接用系统自带的 smartmontools（7.5）：`sudo apt-get install smartmontools`，然后执行 `sudo smartctl -a /dev/sda` 手动查看。也可以配置 `smartd` 定期自检，出问题时报警。

### 5.3 Windows：CrystalDiskInfo

Docker Desktop 的虚拟机看不到物理硬盘，所以 Windows 上**不使用** Scrutiny。建议安装 CrystalDiskInfo（9.9.2）：

```powershell
winget install CrystalDewWorld.CrystalDiskInfo
```

每月打开看一次，每块硬盘的健康状态应显示为"良好"（Good）。重点关注这三项 SMART 属性：重映射扇区（Reallocated Sectors，ID 05）、待映射扇区（Current Pending Sectors，ID C5）、无法修正的扇区（Uncorrectable Sectors，ID C6）。数值不为 0 并且还在增长，就该准备换盘了。

也可以用 smartmontools for Windows（7.5，`winget install smartmontools.smartmontools`）。

### 5.4 看到警告怎么办

1. 立即手动做一次备份：`sudo ./hv backup`；
2. 确认备份能恢复（抽一个文件试试）；
3. 尽快买新硬盘，按 [§6](#6-以后增加或移除硬盘) 迁移。

## 6. 以后增加或移除硬盘

### 6.1 增加一块"额外存储"

1. 装好硬盘并挂载。Linux 用 UUID + `nofail` 写进 fstab，并加进 Docker 的 `RequiresMountsFor`，见 [docs/02-Linux部署.md](02-Linux部署.md) §4。Windows 在"磁盘管理"里分配盘符。
2. 添加并应用：

   ```bash
   sudo ./hv storage list      # 看看新硬盘是否出现在硬盘表里
   sudo ./hv storage add       # 按提示填写名称、路径、只读/读写、是否备份、可见用户
   sudo ./hv storage apply
   ```

3. 硬盘上已经有文件的，想让它们立刻显示出来：`sudo ./hv occ files:scan --all`。

- 系统目录和 HomeVault 自己的目录（程序目录、数据目录、日志、备份仓库等）不能作为额外存储，`add` / `apply` 会直接拒绝，完整列表见 [docs/02-Linux部署.md](02-Linux部署.md) §7.1。
- `apply` 改动挂载时会**重建容器**（包括管理面板），已登录管理面板和安卓管理 App 的人需要重新登录。移除存储时也一样。

### 6.2 移除一个额外存储

```bash
sudo ./hv storage remove 影视资料
sudo ./hv storage apply
```

这只会从 Nextcloud 里取消挂载，**不会删除硬盘上的文件**。拆硬盘之前，还要把它从 Linux 的 fstab 和 `RequiresMountsFor` 里删掉，否则 Docker 会等不到这个挂载点而无法启动。

### 6.3 更换备份盘

1. 装好新硬盘并挂载；
2. 修改 `.env` 里的 `HV_BACKUP_LOCAL_PATH`；
3. `sudo ./hv backup --init`，在新位置初始化仓库并做一次完整备份；
4. 旧备份盘可以先留着一段时间，作为额外的历史备份。

### 6.4 迁移主数据盘（换更大的硬盘）

⚠️ 这是大操作，请先确认有一份可用的最新备份。

1. `sudo ./hv backup`，然后 `sudo ./hv down`；
2. 把旧数据目录**原样复制**到新硬盘，保留权限和属主：
   - Linux：`sudo rsync -aHAX --info=progress2 /mnt/data1/nextcloud-data/ /mnt/newdisk/nextcloud-data/`
   - Windows：`robocopy D:\HomeVault\nextcloud-data N:\HomeVault\nextcloud-data /E /COPY:DAT /DCOPY:DAT /R:1 /W:1`
3. 修改 `.env` 里的 `HV_NC_DATA_PATH` 指向新位置。Linux 上别忘了更新 fstab 和 `RequiresMountsFor`；
4. `sudo ./hv up`，然后 `sudo ./hv doctor`；
5. 确认网页和手机 App 都正常以后，再清理旧硬盘。

容器内部看到的路径始终是 `/var/www/data`，所以 Nextcloud 的配置和备份都不需要跟着改。

## 7. 日志在哪里、保留多久

### 7.1 日志目录

HomeVault 把自己管理的日志都放在一个目录里（`.env` 里的 `HV_LOG_DIR`）：

| 平台 | 默认位置 |
|---|---|
| Linux | `HV_DATA_DIR/logs`，例如 `/srv/homevault/logs`。子目录只有 root 能读，查看时请用 `sudo` |
| Windows | 主数据盘上的 `HomeVault\logs`，例如 `D:\HomeVault\logs`，资源管理器里直接能打开 |

目录结构：

```text
logs/
├── homevault/    hv-YYYY-MM-DD.log              每次运行 hv / hv.ps1 命令（包括定时任务）的记录，每天一个文件；密码类参数记为 ***（见 docs/09 §8.4）
├── backup/       backup-YYYYMMDD-HHMMSS.log     每次备份一个文件（完整的备份输出）
├── nextcloud/    nextcloud.log、audit.log        Nextcloud 运行日志和审计日志；每天轮转为 nextcloud-YYYY-MM-DD.log 等
├── caddy/        access.log                      HTTPS 网关的访问日志（JSON 格式；Cookie、Authorization 等敏感请求头已脱敏）
├── containers/   <服务名>-YYYY-MM-DD.log         每天导出的前一天各容器日志（app、db、caddy、panel……）
└── panel/        panel.log                       管理面板操作记录：登录、退出、立即备份、重启服务、下载日志等
```

说明：

- **Nextcloud 日志**：HomeVault 把 Nextcloud 的 `logfile` 和 `logfile_audit` 指向这个目录（容器内是 `/var/log/homevault/nextcloud/`），单个文件超过 50 MB 时 Nextcloud 自己也会轮转一次（`log_rotate_size`）。审计日志（admin_audit）记录登录、文件操作、分享和设置变更，查可疑操作时看它。
- **Caddy 访问日志**：`access.log` 超过 50 MB 时轮转；轮转出的旧文件超过保留天数后由 Caddy 自己删除。
- **容器日志**：Docker 自己也保存每个容器最近的输出（每个容器最多 3 个 10 MB 的文件），用 `logs [服务名]` 看；更早的内容就靠 `containers/` 里每天导出的文件。
- 日志里会有 IP 地址、用户名、文件名等信息。发给别人求助前，请先检查、删掉不想公开的内容。

### 7.2 怎么查看

| 方式 | 怎么做 |
|---|---|
| **管理面板**（手机、电脑都行） | **日志**页。"日志文件"标签按类别列出上面的文件，可以搜索、选择显示最后 200–5000 行、自动刷新、下载，`.gz` 文件也能直接看；"容器实时日志"标签看各容器最近的输出。备份页的"查看备份日志"会直接跳到对应文件 |
| **Windows 菜单** | **4 查看日志**；**12 打开日志文件夹** |
| **命令行** | 见下面的命令 |
| **资源管理器 / 文件管理器** | Windows 直接打开 `D:\HomeVault\logs`；也可以用 `.\windows\hv.ps1 logs open` |
| **Nextcloud 网页** | 管理员 **管理设置 → 日志**，显示 `nextcloud.log` 的内容 |

```bash
sudo ./hv logs                         # 全部容器的日志（在终端里会持续跟随，Ctrl+C 退出）
sudo ./hv logs app caddy               # 只看某几个服务
sudo ./hv logs list                    # 列出日志文件（最新的在前）和日志目录位置
sudo ./hv logs show app --lines 500    # 某个服务最近 500 行容器日志
sudo ./hv logs show backup/backup-20260926-033000.log     # 某个日志文件（路径相对日志目录，.gz 也可以）
sudo ./hv logs show nextcloud/audit.log --lines 100
```

Windows 用法相同，另外有 `.\windows\hv.ps1 logs open`（在资源管理器里打开日志目录）。

### 7.3 修改保留天数

日志默认保留 **7 天**，安装时可以改，范围 1–365 天。以后任选一种方式修改：

| 方式 | 做法 |
|---|---|
| 命令行 | `sudo ./hv logs retention 30`；不带数字时显示当前值 |
| Windows 菜单 | **5 日志保留天数** |
| 管理面板 | **日志**页或**设置**页，输入天数后点"保存"（由主机执行，Linux 几秒内、Windows 最多约 2 分钟） |

新值写入 `.env` 的 `HV_LOG_RETENTION_DAYS`。Caddy 访问日志的保留天数在 caddy 容器重建后生效（`logs retention` 会自动处理）。

想马上删掉过期日志，不等每天的维护任务：`sudo ./hv logs clean`，或者在面板的日志页点"立即清理旧日志"。

> 保留天数只影响**日志**，和备份的保留策略（`HV_BACKUP_KEEP_DAILY/WEEKLY/MONTHLY`）无关，也不会删除 Nextcloud 回收站或文件版本。

### 7.4 每日维护任务

| 平台 | 任务 | 时间 |
|---|---|---|
| Linux | `homevault-maintenance.timer` → `hv maintenance` | 每天 00:10；错过时开机后补做 |
| Windows | 计划任务 `HomeVault-Maintenance` → `hv.ps1 maintenance` | 每天 04:00（HomeVault 账户需已登录）；错过时开机后补做 |

它依次做这些事：

1. 把**前一天**各容器的日志导出到 `containers/<服务名>-YYYY-MM-DD.log`；
2. 把 `nextcloud.log`、`audit.log` 按日期改名（例如 `audit-2026-09-25.log`），Nextcloud 会自动新建空文件继续写；
3. 删除日志目录里**超过保留天数**的日志文件。只删 `*.log`、`*.log.*`、`*.gz`、`*.txt`，不碰其他文件；
4. 写入 `state/status.json`，给管理面板用。

想立即运行一次：`sudo ./hv maintenance`。管理面板的概览页如果提示"主机状态文件超过 36 小时未更新"，说明这个任务没在运行。

Linux 上 HomeVault 安装的全部 systemd 单元：

| 单元 | 作用 |
|---|---|
| `homevault-maintenance.timer` / `.service` | 每日维护（上面） |
| `homevault-status.timer` / `.service` | 开机 2 分钟后、之后每 5 分钟：给面板写状态文件（`hv status-update`），并处理面板请求 |
| `homevault-requests.path` / `.service` | 面板写入请求文件时立即触发 `hv requests process` |
| `homevault-backup.timer` / `.service` | 每日备份（`hv schedule-backup` 安装） |
| `homevault-firewall.service` | 开机时应用防火墙规则（`hv firewall --apply` 安装） |

不想等定时任务时可以手动运行：`sudo ./hv status-update`（刷新面板状态文件）、`sudo ./hv requests process`（执行面板请求）、`sudo ./hv maintenance`（每日维护）。

查看：`systemctl list-timers 'homevault-*'`；查看某个单元的运行记录：`journalctl -u homevault-maintenance.service`（备份是 `-u homevault-backup.service`）。单元缺失时，重新运行 `sudo ./hv install` 会重新安装（不会重新生成密码）。Windows 的计划任务列表见 [docs/03-Windows部署.md](03-Windows部署.md) §7.5。

### 7.5 其他日志

| 日志 | 位置 | 怎么看 |
|---|---|---|
| 上次成功备份的时间 | `state/last-backup-ok` | `doctor` 和管理面板都会读取它；超过 48 小时会告警 |
| 防火墙（Linux） | systemd 日志 | `journalctl -u homevault-firewall.service`、`sudo ./hv firewall --show` |
| wg-easy（Linux） | 容器日志 | `sudo ./hv logs wg-easy` |
| WireGuard for Windows | WireGuard 自己的日志 | 管理员 PowerShell：`& "$env:ProgramFiles\WireGuard\wireguard.exe" /dumplog /tail` |
| Windows 计划任务 | 任务计划程序 | 任务计划程序库 → 选中 `HomeVault-…` 任务 → "历史记录" |

排查登录问题时，可以查某个 IP 当前被暴力破解防护记了多少次失败：`sudo ./hv occ security:bruteforce:attempts <IP>`。

## 8. 更换局域网 IP 或域名

### 8.1 尽量不要改局域网 IP

局域网 IP 被用在这些地方：

- 访问地址（IP 模式）；
- 手机 App 里保存的服务器地址；
- VPN 客户端配置的 AllowedIPs（`HV_LAN_IP/32`）；
- Linux 的端口绑定；
- 防火墙规则。

所以最好在路由器上用 **DHCP 静态分配**把它固定下来。`doctor` 会检查局域网 IP 有没有变。

### 8.2 如果不得不改（例如换了路由器）

1. 在新路由器上给主机分配 IP（最好还是原来的地址，那样什么都不用改）；
2. 如果 IP 确实变了，修改 `.env`：`HV_LAN_IP`、`HV_LAN_CIDR`（网段变了时），Linux 上还有 `HV_BIND_IP`；IP 模式下还有 `HV_HOST`。也可以重新运行 `sudo ./hv install` 按提示修改（不会重新生成密码），之后请确认 `.env` 里的 `HV_BIND_IP` 也已经是新 IP，否则 Caddy 会绑定到不存在的地址而无法启动；
3. `sudo ./hv up`：会重新计算站点地址、`trusted_domains` 等派生设置，并重建容器；
4. `sudo ./hv firewall --apply`；
5. **更新 VPN 客户端配置**，因为 AllowedIPs 里的主机 IP 变了：
   - Linux：运行 `sudo ./hv vpn finalize`，它会按新 IP 重写 wg-easy 的默认 Allowed IPs 和防火墙钩子（`host` 模式的钩子里写着主机 IP，不改的话 VPN 设备访问不到新地址）。已为 wg-easy 启用二步验证时，按命令打印的步骤在网页上手动修改，然后运行 `sudo ./hv vpn finalize --skip-api`。最后在每台设备上重新导入配置（扫码）；
   - Windows：用 `.\windows\hv.ps1 vpn` 相关命令重新生成客户端配置，见 [docs/04-VPN与DDNS.md](04-VPN与DDNS.md)；
6. **路由器端口转发**改成新 IP；
7. **IP 模式：** 根证书没变，手机不用重新装证书。但 App 里保存的服务器地址变了，需要在 App 里重新添加账户。重新设置自动上传时，把"文件已存在时"选为"跳过"，就不会重复上传，见 [docs/05-安卓手机备份.md](05-安卓手机备份.md)。
   **域名模式：** 只要把域名的 A 记录改成新 IP，App 设置都不用动。这就是推荐域名模式的原因之一。
8. `sudo ./hv doctor`。

### 8.3 更换域名（域名模式）

1. 为新域名添加 A 记录，指向局域网 IP；
2. 修改 `.env` 里的 `HV_HOST`。DNS 服务商也变了的，重新运行安装并指定新的服务商和密钥：`sudo ./hv install --host <新域名> --dns-provider <服务商> --dns-id <ID> --dns-secret-file <存放密钥的文件>`；
3. `sudo ./hv up`，Caddy 会自动为新域名申请证书；
4. 各设备的 App 里重新添加账户（新地址）；
5. 如果 VPN 的对外地址 `WG_HOST` 也用了旧域名，同时更新 `WG_HOST` 和 DDNS 设置（`sudo ./hv ddns setup`）。然后运行 `sudo ./hv vpn finalize` 把新地址写进 wg-easy（启用了 wg-easy 二步验证时，在它的管理界面里手动修改主机地址），再重新导入客户端配置。

## 9. 轮换密钥和密码

| 项目 | 什么时候换 | 怎么换 |
|---|---|---|
| 家人的 Nextcloud 密码 | 怀疑泄露时 | 本人在 **个人设置 → 安全** 修改；忘记时管理员执行 `sudo ./hv user reset-password <用户名>` |
| 管理员 `hvadmin` 的密码 | 安装后改成自己的；怀疑泄露时 | 网页上修改，或 `sudo ./hv user reset-password hvadmin` |
| 二步验证 | 换手机、身份验证器丢失 | 用备用码登录后重新绑定，或管理员执行 `sudo ./hv user reset-2fa <用户名>` |
| 应用密码 | 设备丢失、不再使用 | **个人设置 → 安全 → 设备和活动链接** 里撤销，再在新设备上重新登录 |
| wg-easy 管理员密码（Linux） | 怀疑泄露时 | 在 wg-easy 网页的账户菜单里修改。忘记时运行 `sudo ./hv vpn reset-password`：生成新密码并保存到 `secrets/wg_easy_admin_password`，同时会清除 wg-easy 的二步验证，之后请立刻重新启用 |
| VPN 客户端密钥 | 设备丢失、怀疑泄露 | 删除该客户端并重新创建，见 [§10](#10-手机丢了怎么办) |
| DNS 服务商 API 密钥 | 定期（例如每年）或怀疑泄露时 | 在服务商控制台创建新密钥 → Linux：`sudo ./hv install --dns-id <新ID> --dns-secret-file <存放新密钥的文件>`；Windows：删除 `secrets\` 里 `caddy-dns` 开头的密钥文件（或文件夹）后重新运行一键安装，向导会重新询问 → `sudo ./hv restart caddy` → 确认证书正常（`doctor`）后，删除旧密钥。DDNS 也在用这个服务商的话，再运行一次 `sudo ./hv ddns setup` |
| S3 备份访问密钥 | 定期或怀疑泄露时 | 同上，写进 `secrets/backup.env`，再运行 `sudo ./hv backup` 验证 |
| restic 备份密码 | 仅在怀疑泄露时 | restic 支持给仓库添加新密钥、删除旧密钥（`key add` / `key remove`）；改完后必须同步更新 `secrets/restic_password`，并重新离线保存。⚠️ 如果备份盘本身也可能落到了别人手里，更稳妥的做法是换一个全新的仓库重新备份 |
| 数据库 / Redis 密码 | 一般无需轮换 | 它们只在内部网络中使用，外部访问不到。确实要换的话，先完整备份，再参考 Nextcloud 和 PostgreSQL 的官方文档手动操作 |

⚠️ 任何时候都不要把 `secrets/` 里的文件内容发到聊天工具、论坛或截图里。

## 10. 手机丢了怎么办

按顺序做，越快越好。

### 第 1 步：撤销这台手机的 Nextcloud 登录

- 让手机的主人（或你帮他）在电脑上登录 Nextcloud 网页 → 右上角头像 → **个人设置 → 安全 → 设备和活动链接**；
- 找到丢失的手机（名称通常包含手机型号或 "Android"），点它旁边的菜单，选择**撤销**。如果菜单里有**擦除设备**，可以选它：手机下次联网时，App 会删除本地数据；
- 同一页面里，这台手机上 DAVx⁵ 等 App 用的应用密码，也一并撤销。
- 丢的是**管理员**的手机，而且上面装了 HomeVault 管理 App：在管理员账户的同一页面里，撤销名为"**HomeVault 管理面板（…）**"的设备，面板会话会在 5 分钟内失效。

### 第 2 步：删除这台手机的 VPN 配置

- **Linux：** 登录 wg-easy 管理界面 `https://HV_HOST:8443`，找到这台手机对应的客户端，**删除**（或先禁用）。
- **Windows：**

  ```powershell
  .\windows\hv.ps1 vpn list
  .\windows\hv.ps1 vpn remove <客户端名称>
  ```

删除后，这台手机上的 VPN 配置就连不上了，即使别人解开了手机锁屏也一样。

### 第 3 步：处理二步验证

如果丢的手机上装着**身份验证器 App**：

- 用离线保存的**备用码**登录，然后重新绑定新手机；
- 或者让管理员执行 `sudo ./hv user reset-2fa <用户名>`，下次登录时重新绑定。

丢的是管理员自己的手机，而且备用码也找不到了，也可以用 `reset-2fa` 自救，因为这个命令在服务器上执行，不需要登录网页。

### 第 4 步：检查

- 看审计日志里，这个账户在手机丢失后有没有异常操作（`logs/nextcloud/audit.log`，见 [§7](#7-日志在哪里保留多久)）；
- 为保险起见，修改该用户的 Nextcloud 密码；
- 手机找回来了，或者换了新手机：按 [docs/05-安卓手机备份.md](05-安卓手机备份.md) 重新设置。要用**新的** VPN 配置，登录 App 时会生成新的应用密码。

> 因为 VPN 默认只允许访问 HomeVault 主机（`HV_VPN_LAN_ACCESS=host`），而且 Nextcloud 强制二步验证，即使在你撤销之前有人拿到了这台手机，能造成的影响也很有限。但撤销越早越好。

## 11. 管理面板与安卓管理 App

管理面板（服务名 `panel`）和它依赖的 `socket-proxy` 随 HomeVault 一起启动、一起更新，平时不需要单独维护。完整说明见 [docs/10-安卓管理App与管理面板.md](10-安卓管理App与管理面板.md)。

### 11.1 日常

- 地址：`https://HV_HOST:9443`（`HV_PANEL_PORT`），只能在局域网和 VPN 里打开；
- 登录：Nextcloud 管理员账户 + 二步验证；每次登录会在 Nextcloud 的 **个人设置 → 安全 → 设备和活动链接** 里出现一个"HomeVault 管理面板（IP）"设备，退出时自动删除。看到不认识的这类设备，立即撤销；
- 面板能做的操作只有：重启部分服务、立即备份、修改日志保留天数、清理旧日志、下载日志 / 根证书 / App。其他管理仍然在服务器上用命令或 Windows 菜单完成；
- 面板的操作记录在 `logs/panel/panel.log`。

### 11.2 面板出问题时

```bash
sudo ./hv status                 # panel、socket-proxy 是否在运行
sudo ./hv logs panel             # 面板日志
sudo ./hv logs socket-proxy
sudo ./hv restart panel          # 重启面板（面板页面里不能重启自己）
```

面板容器故障**不影响** Nextcloud 和手机备份。

### 11.3 更新安卓管理 App

1. 服务器上下载最新的安装包：

   ```bash
   sudo ./hv android fetch
   ```

   它从 GitHub Releases 的最新版本下载 APK（仓库由 `.env` 的 `HV_ANDROID_RELEASE_REPO` 指定，默认就是本项目），保存为 `state/app/homevault.apk`。服务器上不了 GitHub 时，在别处下载好后用 `sudo ./hv android fetch --file <APK文件>` 导入。
2. 手机打开面板 → **设置** → **下载安卓应用**，下载后直接覆盖安装。
3. 提示"签名不一致"时，先卸载旧版再装（原因见 [docs/10-安卓管理App与管理面板.md](10-安卓管理App与管理面板.md) §4.5）。

也可以直接从 <https://github.com/yuelanxian/-/releases> 下载 `homevault-android.apk`。
