# 01 · 架构与安全

本文说明 HomeVault 由哪些部分组成、数据怎样流动、每一层安全措施防的是什么，以及 HomeVault **防不了**什么。部署前建议通读一遍，特别是标有 ⚠️ 的地方。

## 1. 整体架构

### 1.1 组件

| 组件（Compose 服务名） | 作用 | 对外可见？ |
|---|---|---|
| `caddy` | HTTPS 入口：提供证书、来源地址过滤，并把请求转给 Nextcloud 和管理面板 | 只在 `HV_BIND_IP`（Linux 默认是局域网 IP；Windows 是 `0.0.0.0`，由 Windows 防火墙限制）上监听 TCP `HV_HTTPS_PORT`（默认 443）、`HV_HTTP_PORT`（默认 80，只做跳转）、`HV_ADMIN_PORT`（默认 8443，Linux 上的 VPN 管理界面）、`HV_PANEL_PORT`（默认 9443，管理面板） |
| `app` | Nextcloud 34（Apache 版官方镜像） | 否，只有 Caddy 能访问 |
| `cron` | Nextcloud 后台任务，每 5 分钟运行一次 | 否 |
| `db` | PostgreSQL 18 | 否，只在内部网络 `backend` 上 |
| `redis` | Redis 8：缓存和文件锁 | 否，只在内部网络 `backend` 上 |
| `panel` | 管理面板（安卓管理 App 的服务端），在本机从 `panel/` 源码构建 | 否，只经 Caddy 的 `HV_PANEL_PORT` 访问，并且只有 Nextcloud 管理员能登录（见 [docs/10-安卓管理App与管理面板.md](10-安卓管理App与管理面板.md)） |
| `socket-proxy` | Docker 接口过滤代理：面板只能通过它查看容器状态、日志和重启容器 | 否，只在内部网络 `dockerapi` 上，唯一挂载 `docker.sock`（只读）的容器 |
| `wg-easy`（仅 Linux，profile `vpn`） | WireGuard 服务端和它的网页管理界面 | 只开放 UDP `WG_PORT` |
| WireGuard for Windows（仅 Windows，系统服务） | WireGuard 服务端，隧道服务名为 `WireGuardTunnel$homevault` | 只开放 UDP `WG_PORT` |
| `backup`（profile `tools`） | restic 备份，按需临时运行 | 否 |
| `ddns-go`（可选，profile `ddns`） | 把家里的公网 IP 更新到域名解析 | 否，不开网页界面 |
| `scrutiny`（可选，仅 Linux，profile `monitor`） | 硬盘 SMART 监控 | 只绑定 `127.0.0.1` |

### 1.2 数据怎么走

```text
外出的手机 ──(WireGuard, UDP WG_PORT)──▶ 路由器 ──▶ 主机上的 WireGuard
                                                          │
在家的手机 / 电脑 ──(局域网, HTTPS)──────────────────────────┤
                                                          ▼
                                          Caddy（HV_LAN_IP:443，TLS）
                                             │                    └─ :9443 ─▶ 管理面板 ─▶ socket-proxy（只读 + 重启）
                                             ▼
                                            Nextcloud（app:80，内部网络）
                                             │                    │
                                   PostgreSQL / Redis    硬盘（主数据盘 + 额外存储）
```

- **Linux：** 手机（VPN 地址 `10.99.77.x`）→ WireGuard → wg-easy 容器做地址转换（MASQUERADE）→ 访问主机的 `HV_LAN_IP:HV_HTTPS_PORT` → Docker 转发给 Caddy → Nextcloud。在家的设备直接访问 `HV_LAN_IP`。
- **Windows：** WireGuard for Windows 以系统服务运行，隧道网卡地址是 VPN 网段的第一个地址（例如 `10.99.77.1`）。手机仍然访问 `https://HV_LAN_IP`。HomeVault 打开隧道网卡的"弱主机模式"，让发往局域网 IP 的数据包也能从隧道网卡进来。Windows 上不做地址转换，所以 VPN 客户端本来就只能访问这台主机。详见 [docs/03-Windows部署.md](03-Windows部署.md)。

### 1.3 一个地址走天下

手机 App 只能保存一个服务器地址。HomeVault 让在家和出门都使用**同一个地址** `https://HV_HOST[:端口]`：

| 模式 | `HV_HOST` | 证书 | 适合谁 |
|---|---|---|---|
| **IP 模式**（`HV_TLS_MODE=internal`） | 主机的局域网 IPv4，例如 `192.168.1.10` | Caddy 本地 CA 签发。需要在每台手机和电脑上安装一次根证书 | 没有域名，或想先快速跑起来 |
| **域名模式**（`HV_TLS_MODE=acme-dns`，推荐） | 一个域名，例如 `cloud.example.com`，它的**公网 A 记录指向局域网 IP** | Let's Encrypt 正式证书（DNS-01 验证），手机不用装证书 | 已有域名（做 DDNS 本来就需要域名） |

VPN 客户端配置里的 AllowedIPs 包含 `HV_LAN_IP/32`，所以出门时，发往这个地址的流量会自动走隧道；其余上网流量不经过家里（分流）。

## 2. 威胁模型：我们在防什么

| 威胁 | 例子 | HomeVault 的对策 |
|---|---|---|
| 互联网上的扫描和漏洞利用 | 批量扫描器找到你的 Nextcloud，利用未修补的漏洞 | 网页服务根本不在公网上。唯一开放的是 WireGuard UDP 端口，它不回应没有正确密钥的数据包 |
| IPv6 意外暴露 | 光猫给每台设备分配了公网 IPv6，且没开 IPv6 防火墙 | 所有 TCP 端口都显式绑定到 IPv4 地址，Windows 防火墙规则也只放行 IPv4 网段 |
| 猜密码、撞库 | 用泄露的密码尝试登录 | 强制二步验证、密码至少 12 位、暴力破解防护、客户端只能用应用密码 |
| 手机丢失或被盗 | 别人拿到手机里的 VPN 配置和已登录的 App | 每台设备一个应用密码和一个 VPN 配置，可以单独撤销。VPN 默认只能访问这台主机，进不了家里其他设备 |
| 硬盘被盗或送修 | 硬盘被人拆走读取 | 建议启用 LUKS2 / BitLocker / 设备加密（见第 9 节） |
| 误删、勒索软件加密了同步的文件 | 电脑中毒，同步盘里的文件被加密后同步回服务器 | Nextcloud 回收站和版本历史，加上 restic 每晚快照（可以恢复到任意保留的时间点） |
| 硬盘损坏 | 主数据盘坏道或整盘报废 | 备份到另一块物理硬盘，可选异地 S3 备份，SMART 监控提前预警 |
| 家里其他设备被攻破 | 局域网里的智能设备中毒 | 数据库和 Redis 在内部网络上，不对局域网开放；Nextcloud 需要登录并通过二步验证 |

## 3. 安全措施逐层说明

### 3.1 路由器只转发一个 UDP 端口

- 路由器上只添加**一条**端口转发：`UDP WG_PORT → HV_LAN_IP`。安装程序会在 20000–60000 之间随机选择一个端口，避开 WireGuard 默认的 51820，降低被针对性扫描和干扰的概率。
- **不要**转发 TCP 443、80、8443 等任何其他端口。
- ⚠️ **不要使用路由器或光猫的 DMZ 功能。** DMZ 会把**所有端口**都转发到这台电脑。而 Docker 发布的端口会绕过 ufw 等主机防火墙（见 3.4），DMZ 等于把所有服务直接放到公网上。
- WireGuard 对没有正确密钥的数据包不作任何回应。所以即使别人扫到这个端口，也看不出这里有服务。

### 3.2 只监听 IPv4、只绑定指定地址（为什么 IPv6 很重要）

Docker 的默认行为：如果端口写成 `443:443`，不指定地址，Docker 会同时在 `0.0.0.0`（所有 IPv4 地址）**和 `[::]`（所有 IPv6 地址）**上监听。对 IPv6 连接，Docker 由用户态代理转发，容器看到的来源地址变成一个内部私有地址，**真实来源被隐藏**。

这在国内家庭网络里很危险：

- 运营商普遍给家里**每台设备**分配公网 IPv6 地址；
- 光猫的 IPv6 防火墙（常叫"IPv6 SPI""IPv6 会话保护"等）有时是关着的；
- 结果：一个没指定地址的 `443:443`，可能被互联网上任何人通过 IPv6 直接访问，而 Caddy 看到的却是"内部地址"。

HomeVault 的做法：

- 所有发布的 TCP 端口一律写成 `"${HV_BIND_IP}:${HV_HTTPS_PORT}:${HV_HTTPS_PORT}"` 这种形式，**只绑定一个 IPv4 地址**。
- Linux 上 `HV_BIND_IP` 默认就是主机的局域网 IP（`HV_LAN_IP`）。
- Windows 上 Docker Desktop 的默认值是 `0.0.0.0`，由 Windows 防火墙规则只放行局域网和 VPN 的 IPv4 网段，所以 IPv6 连接不会被放行。
- 数据库、Redis、Nextcloud 的 80 端口、wg-easy 的网页端口、管理面板容器本身的端口、socket-proxy、ddns-go、Scrutiny **一律不发布**（Scrutiny 只绑定 `127.0.0.1`）。管理面板只经过 Caddy 的 `HV_PANEL_PORT` 访问。
- 在 Linux 上，`doctor` 会检查每个发布端口是否只绑定在 IPv4 的指定地址上。

### 3.3 Caddy 来源地址白名单：只是"兜底"

Caddy 会检查每个请求的来源地址。来源不在 `HV_ALLOWED_CIDRS`（默认 `private_ranges 100.64.0.0/10`，即所有私有网段加运营商级 NAT 网段）里的请求，会被直接断开连接（abort），连跳转都不返回。这条规则写在 `route {}` 里，保证先检查、后跳转。

⚠️ 但要清楚它的局限：

- Linux 上，VPN 流量经过 wg-easy 的地址转换后，来源变成 Docker 的内部地址；
- Windows 上，Docker Desktop 转发进来的连接，来源通常也是一个内部地址；
- 这两种情况下，Caddy 看到的总是"私有地址"，白名单都会放行。

所以它只是**纵深防御的最后一道兜底**，真正起作用的是 3.1（路由器只开 UDP）、3.2（只绑 IPv4）和 3.4（主机防火墙）。

### 3.4 主机防火墙

**为什么 ufw 不够：** Docker 发布的端口，流量在进入 ufw 规则之前就被 Docker 的 iptables 规则转走了，Docker 官方文档明确说这会"实际上忽略你的防火墙配置"。所以只在 ufw 里写"禁止 443"是没用的。

**Linux：`./hv firewall`**

| 子命令 | 作用 |
|---|---|
| `sudo ./hv firewall --apply` | 应用规则（可以重复执行，不会重复添加） |
| `sudo ./hv firewall --show` | 查看当前规则 |
| `sudo ./hv firewall --remove` | 删除 HomeVault 添加的规则 |

它做两件事：

1. 在 Docker 专门留给用户的 `DOCKER-USER` 链里挂一条专用的 `HOMEVAULT` 链：发往 HomeVault 网页端口（HTTP/HTTPS/VPN 管理端口/管理面板端口）的**新 TCP 连接**，如果来源 IPv4 不在 `HV_ALLOWED_CIDRS` 里，一律丢弃。规则由 `homevault-firewall.service` 在每次 Docker 启动后自动恢复。
2. 如果系统装了 ufw：默认拒绝所有入站连接，**只允许局域网访问 SSH**。

⚠️ 应用规则后，只能从局域网 SSH 登录这台主机。Linux 上 VPN 客户端的流量经 wg-easy 地址转换后，在主机看来来自 Docker 内部网段（`HV_FRONTEND_SUBNET`），所以**连着 VPN 也 SSH 不进来**（`host`、`full` 两种访问范围都一样）。需要在外面远程管理时，请回家处理，或自行在 ufw 里放行这个网段的 SSH（只用密钥登录）。

**Windows：`.\windows\hv.ps1 firewall --apply`**（`--show` 查看）

- 允许来自局域网网段（`HV_LAN_CIDR`）和 VPN 网段（`HV_VPN_CIDR`）的 TCP 连接访问 `HV_HTTP_PORT`、`HV_HTTPS_PORT`、`HV_ADMIN_PORT`、`HV_PANEL_PORT`，规则适用于所有网络类型（`-Profile Any`）。WireGuard 隧道网卡通常被 Windows 识别为"公用网络"，所以必须这样设置。
- 同样这几个端口，另加两条**阻止**规则：其他任何 IPv4 来源、所有 IPv6 来源（阻止规则优先于任何允许规则）。
- 允许 UDP `WG_PORT` 入站。
- **检查并警告** Docker Desktop 安装时可能添加的宽泛"允许"规则（针对 `com.docker.backend.exe` 程序）。这类规则会放行任意来源，绕过上面按地址限制的规则。详见 [docs/03-Windows部署.md](03-Windows部署.md)。

### 3.5 VPN 访问范围：默认只能访问这台主机

`HV_VPN_LAN_ACCESS` 控制 VPN 客户端能访问哪些地址：

| 取值 | 能访问 | 客户端 AllowedIPs | 适合 |
|---|---|---|---|
| `host`（**默认**） | 只有 HomeVault 主机 | `HV_VPN_CIDR, HV_LAN_IP/32` | 绝大多数家庭 |
| `full` | 整个家庭局域网（路由器、NAS、打印机……），但**不包括** Docker 内部网络，也**不能**经家里上网 | `HV_VPN_CIDR, HV_LAN_CIDR` | 确实需要在外访问家里其他设备，并且清楚风险的人 |

- **Linux：** wg-easy 默认会把 VPN 客户端的流量转发到任何地方。HomeVault 在安装时会改写 wg-easy 的防火墙钩子：`host` 模式下，只允许转发到 `HV_LAN_IP`；`full` 模式下，只允许转发到家庭局域网 `HV_LAN_CIDR`，并且**丢弃**发往 Docker 内部网络（`HV_FRONTEND_SUBNET`）的流量，否则 VPN 客户端可以绕过 Caddy 直接访问 Nextcloud、管理面板的容器端口。两种模式下，其余流量（包括去互联网的）一律丢弃，家里的宽带**不会**成为 VPN 设备的上网出口；也都**禁止 VPN 客户端直接访问 wg-easy 管理端口**。
- **Windows：** Windows 版根本不做 NAT 和转发，VPN 客户端天然只能访问这台主机。
- **分流：** 客户端只把去往家里的流量送进隧道，手机平时上网不绕道家里，更省电，也不会拖慢速度。

⚠️ 一个手机 VPN 私钥泄露时，在 `host` 模式下，对方最多只能看到 HomeVault 的 HTTPS 登录页，还要过密码和二步验证。在 `full` 模式下，对方还能访问你家路由器的管理页、NAS 等设备，所以请谨慎开启。

**wg-easy 管理界面（Linux）：** 只能通过 `https://HV_HOST:HV_ADMIN_PORT`（默认 8443）访问，前面同样有 Caddy 的来源过滤。wg-easy 自己的登录要求密码至少 12 位。它**没有登录频率限制**，所以：

- 请在 wg-easy 的账户菜单里**启用二步验证**；
- 管理端口不要做端口转发。

**跨站请求兜底（管理面板 9443 和 wg-easy 8443）：** wg-easy 自己没有防跨站请求伪造（CSRF）的措施，而它的"钩子"设置能在服务器上执行命令。所以 Caddy 在这两个管理端口前加了一道检查：浏览器从**其他网站或其他端口**发来的修改类请求（POST、PUT、DELETE 等）一律返回 403"跨站请求已拒绝"。判断依据是浏览器自动附带的 `Sec-Fetch-Site` 头（没有这个头时比较 `Origin` 和本站地址）。正常使用不受影响；curl 等非浏览器客户端也不受影响。管理面板自身另有一层防护（会话 Cookie `SameSite=Strict` + CSRF 令牌）。

### 3.6 TLS：永远 HTTPS

所有访问都走 HTTPS；80 端口只负责跳转到 HTTPS。Caddy 会发送 HSTS 头 `Strict-Transport-Security: max-age=15552000`（180 天），满足 Nextcloud 自带的安全检查。Caddy 只启用 HTTP/1.1 和 HTTP/2，不开放 UDP 443（HTTP/3），减少一个需要开放的端口。

#### IP 模式：Caddy 本地 CA

- Caddy 自己生成一个名为 **"HomeVault Local CA"** 的根证书。根证书有效期约 10 年，中间证书每 7 天、网站证书每 12 小时自动轮换，不需要人工干预。
- 每台访问 HomeVault 的设备都要**安装并信任一次根证书**：
  - 用 `./hv ca --export <路径>`（Windows：`.\windows\hv.ps1 ca`）导出根证书，命令会显示 SHA-256 指纹和各系统的安装方法；在局域网或 VPN 里也可以从管理面板 `https://HV_HOST:9443/ca.crt` 下载（只有证书，不含私钥），安装后同样要核对指纹；
  - Nextcloud 安卓 App 信任用户自行安装的 CA 证书；
  - 电脑上必须装进**系统信任库**。因为服务器发送了 HSTS，Nextcloud 桌面客户端不再允许"仍然信任此证书"。

⚠️ **根证书私钥的风险（请务必理解）：**

- 任何设备一旦信任了这个根证书，拿到**根私钥**的人就能为**任何网站**（包括银行、邮箱）签发你的设备会信任的证书，从而冒充这些网站。Caddy 的本地 CA **不能限制**它只给 HomeVault 签证书。
- 根私钥保存在 Caddy 的数据卷里（容器内 `/data/caddy/pki/authorities/local/`），为了灾难恢复，也**包含在 restic 备份中**（备份是加密的）。
- 所以：
  1. 保护好主机本身和 restic 备份密码；
  2. 不要把根证书装到不属于你家的设备上；
  3. 设备报废或转手前，从设备上删除这个根证书；
  4. 有条件时改用**域名模式**，设备上就不需要安装任何自签根证书。

#### 域名模式：Let's Encrypt + DNS-01

- 用你自己的域名（例如 `cloud.example.com`），把它的**公网 DNS A 记录指向局域网 IP**（例如 `192.168.1.10`）。
- Caddy 通过 DNS 服务商的 API 完成 **DNS-01 验证**，申请 Let's Encrypt 证书。这种方式**不需要开放任何端口**，并且证书会自动续期。
- 支持的 DNS 服务商（`HV_DNS_PROVIDER`）：阿里云 `alidns`、腾讯云 `tencentcloud`、Cloudflare `cloudflare`。API 密钥只保存在 HomeVault 目录的 `secrets/` 里（安装程序写入）。
- ⚠️ **给 API 密钥最小权限：**
  - 阿里云：用 RAM 子用户，只授予解析记录相关权限；
  - Cloudflare：Token 只授予这一个域名（Zone）的 DNS 编辑权限；
  - 腾讯云：用只有 DNSPod 权限的子账号密钥。
- 需要知道的两点：
  - 证书会公开记录在"证书透明度"日志里，也就是说**域名本身是公开的**。请用一个不显眼的子域名。
  - 有些路由器开启了"DNS 重绑定保护"，会丢弃解析到私有 IP 的结果，导致在家打不开域名。处理方法见 [docs/04-VPN与DDNS.md](04-VPN与DDNS.md)。

### 3.7 Nextcloud 加固：每次启动都重新检查

Nextcloud 容器**每次启动**时，HomeVault 的钩子脚本都会把下列设置恢复到安全值（也可以手动执行 `./hv harden` 重新应用并显示关键设置）：

| 设置 | 效果 |
|---|---|
| 强制 TOTP 二步验证 | 所有用户第一次登录时必须绑定身份验证器 App（任何支持 TOTP 的 App 都可以） |
| `token_auth_enforced` | 客户端和 WebDAV **不能用登录密码**，只能用应用密码或 App 登录流程生成的令牌 |
| 暴力破解防护 | 登录失败次数多了会自动变慢（Nextcloud 默认开启，HomeVault 保持开启） |
| 公开分享链接关闭 | 除非设置 `HV_ALLOW_PUBLIC_LINKS=true`。即使开启，链接也只有连上 VPN 或在家里的人才能打开 |
| 联邦共享关闭 | 不与其他 Nextcloud 服务器互相分享 |
| 审计日志（admin_audit）开启 | 记录登录、文件操作、分享、设置变更等 |
| 密码策略 | 密码最少 `HV_PASSWORD_MIN_LENGTH` 位（默认 12） |
| 禁止在网页上新建"本地"外部存储 | 只有 HomeVault 的 `storage` 命令能挂载主机目录，防止管理员账户被盗后挂载主机上的任意目录 |
| 关闭"回传数据"类应用 | 例如使用情况调查等 |
| `APACHE_DISABLE_REWRITE_IP=1` + `TRUSTED_PROXIES` | 防止客户端伪造 `X-Real-IP` 请求头，冒充来源地址绕过暴力破解防护 |
| 回收站和版本保留策略 | 自动清理过期内容，同时保留一段时间，方便后悔 |

⚠️ **关于暴力破解防护的一点提醒：** 经过 VPN 地址转换或 Docker Desktop 转发后，很多客户端在 Nextcloud 看来可能来自**同一个内部地址**。某台设备密码输错多次后，其他设备也可能跟着变慢。这是正常的，**不要**为了"解决"这个问题把这个地址加进白名单，否则暴力破解防护就等于关掉了。

### 3.8 应用密码：每台设备一把钥匙

- 手机 App 和桌面客户端用"登录流程"登录时，Nextcloud 会自动为这台设备生成一个**应用密码**。
- DAVx⁵、WebDAV、rclone 等第三方客户端，需要在 **个人设置 → 安全** 页面底部手动创建应用密码。启用二步验证后，这是它们唯一的登录方式。
- 建议给每台设备单独起名，例如"妈妈的小米 14"。设备丢失时，在同一页面撤销它即可，其他设备不受影响（见 [docs/08-日常运维与升级.md](08-日常运维与升级.md)）。

### 3.9 密钥和密码怎样保存

| 项目 | 做法 |
|---|---|
| 生成 | 用密码学安全的随机数生成，每个 32 位字母和数字 |
| 存放 | 每个密钥单独存成 `secrets/` 目录下的一个文件：`postgres_password`、`redis_password`、`nextcloud_admin_password`、`restic_password`，Linux 启用 VPN 时还有 wg-easy 管理员密码 `wg_easy_admin_password`，以及可选的 DNS API 密钥（域名模式）、`backup.env`（S3 备份）、`ddns-go.yaml`（DDNS） |
| 权限（Linux） | `secrets/` 目录权限 0700，属主 root，普通用户无法进入。里面的文件是 0644，这样容器里的非 root 进程能读到挂载进去的文件 |
| 权限（Windows） | `secrets\` 目录的访问控制只允许当前用户、SYSTEM 和 Administrators |
| 传给容器 | 数据库、Redis、Nextcloud 管理员、restic 密码通过 `*_FILE` 环境变量或 Compose `secrets:` 传入，`docker inspect` 里看不到明文。第三方服务的凭据（S3 AccessKey，以及首次启动时 wg-easy 的初始化密码）以环境变量传给对应容器，在该容器的详情（`docker inspect`）里可见，所以请只给这些密钥最小权限 |
| 显示 | 只有 Nextcloud 管理员初始密码和 restic 备份密码，会在安装结束时**显示一次** |
| wg-easy 初始密码 | 只在第一次启动时放在 `secrets/wg-easy-init.env` 里。wg-easy 启动成功后，这个文件会被删除，容器随之重建 |

⚠️ `.env`、`secrets/`、`clients/` 都在 `.gitignore` 里，**不要**把它们提交到 Git，也不要发到聊天群里。

### 3.10 容器加固

- 支持的容器都设置了 `no-new-privileges`；Caddy 去掉所有特权（`cap_drop: ALL`），只保留绑定低端口的能力。
- 管理面板以非 root 用户（uid 65532）运行，根文件系统只读，去掉全部特权；它**没有** `docker.sock`，只能经过 `socket-proxy` 查看容器状态、日志和重启容器，对主机的操作只能写"请求文件"，由主机上的任务检查后执行（只认立即备份、清理日志、修改日志保留天数三种）。详见 [docs/10-安卓管理App与管理面板.md](10-安卓管理App与管理面板.md) §7。
- 数据库和 Redis 只连接到 `internal: true` 的内部网络，完全不能访问外网，也不能被外面访问。
- 所有镜像都**固定版本号**（例如 `nextcloud:34-apache`、`postgres:18-alpine`），绝不使用 `latest`，避免某次拉取时意外跨越大版本。
- 容器日志自动轮转（每个容器最多保留 3 个 10 MB 的日志文件），不会把磁盘写满。
- 每个服务都有健康检查，并设置 `restart: unless-stopped`，崩溃或重启后自动恢复。

## 4. 备份是加密的

- restic 仓库有密码保护，备份盘或云存储上只有加密后的数据块。
- 默认每晚 `HV_BACKUP_TIME`（03:30）运行一次，按"每日 7 份、每周 4 份、每月 12 份"保留快照。每周会随机抽查 5% 的备份数据，确认可以正常读出。
- ⚠️ **restic 密码只在安装时显示一次。** 请抄在纸上，和其他重要证件放在一起，或存进你信任的密码管理器。**密码丢了，备份就再也打不开了；** 反过来，别人拿到了密码和备份盘，就能读出全部数据。
- 取舍说明：为了不让服务长时间停止，HomeVault 只在**导出数据库**那几秒到几分钟里开启 Nextcloud 维护模式。文件本身是在服务运行时备份的，备份过程中正在上传的文件可能和数据库记录不完全一致。整机恢复后，HomeVault 会执行 `maintenance:data-fingerprint` 和 `files:scan --all` 来修正。
- 备份目标应该在**另一块物理硬盘**上。有条件时再加一份异地备份（S3 兼容存储，例如阿里云 OSS），做到"3-2-1"。详见 [docs/07-备份与恢复.md](07-备份与恢复.md)。

## 5. 磁盘加密（静态数据保护）

HomeVault 不会替你加密硬盘，但**强烈建议**你自己启用：

| 平台 | 方案 | 要点 |
|---|---|---|
| Linux | **LUKS2** | 数据盘用 `cryptsetup luksFormat --type luks2` 加密。开机自动解锁有两种方式：①密钥文件放在系统盘上（只防"单独偷走数据盘"）；②用 `systemd-cryptenroll` 绑定 TPM2 芯片。一定要备份 LUKS 头（`cryptsetup luksHeaderBackup`）和恢复密钥。步骤见 [docs/02-Linux部署.md](02-Linux部署.md) |
| Windows 专业版 / 企业版 / 教育版 | **BitLocker** | 系统盘和数据盘都加密，数据盘设置"自动解锁"（前提是系统盘也已加密）。恢复密钥要离线保存 |
| Windows 家庭版 | **设备加密** | 家庭版没有完整的 BitLocker，只有"设备加密"，它会加密系统盘和内置硬盘，**不包括 USB 移动硬盘** |

⚠️ 如果给 BitLocker 设置了开机 PIN，或者 LUKS 需要在开机时手动输入密码，**停电后来电时主机就无法无人值守地自动开机**，会一直停在输入界面。家用服务器通常选择 TPM 自动解锁，再加上"系统盘加密 + 数据盘自动解锁"的组合。

### 为什么不开 Nextcloud 自带的"服务端加密"

Nextcloud 有一个"服务端加密"功能，HomeVault **故意不启用**，原因如下：

- 它主要是为了保护放在**不受信任的外部存储**上的文件而设计的；而 HomeVault 的数据就在你自己的硬盘上。
- 解密用的密钥和数据放在同一台服务器上。主机被攻破时，它挡不住攻击者；硬盘被偷时，全盘加密（LUKS/BitLocker）已经能很好地防护。
- 开启后文件在硬盘上不再是普通文件：你没法在资源管理器或文件管理器里直接查看；备份和恢复都更复杂；密钥一旦出问题，**数据可能永久丢失**；性能也会下降。
- 结论：用**全盘加密 + 加密备份**来保护静态数据，更简单，也更可靠。

## 6. HomeVault **不能**防护的情况

请诚实地认清边界：

1. **主机本身被攻破。** 如果这台电脑的操作系统中了木马，或者有人拿到了 root/管理员权限，他能读到所有数据、密钥和根 CA 私钥。请保持系统更新，不要在这台电脑上随意安装软件、浏览不明网站。
2. **开机状态下的物理接触。** 全盘加密只在关机或硬盘被拆走时有效。开机并已解锁的电脑被人坐在键盘前操作，Windows 上尤其要靠自动锁屏任务和强密码。
3. **Windows 自动登录的密码。** Sysinternals Autologon 把密码加密存在注册表里，但**任何有管理员权限的人都能取出来**。所以要用专门的本地账户，并设置不同于其他账户的密码。
4. **你把密码、应用密码或 VPN 配置交给了别人**（包括钓鱼网站）。二步验证能挡住大部分只拿到密码的情况，但挡不住你主动把二步验证码告诉骗子。
5. **所有备份都放在家里。** 火灾、水灾、被盗可能让主数据盘和备份盘同时损失。重要数据请加一份异地备份（云存储，或定期把 USB 备份盘放到别处）。
6. **上游软件的漏洞。** Nextcloud、WireGuard、Docker、Caddy 等出现零日漏洞时，只能靠及时更新（见 [docs/08-日常运维与升级.md](08-日常运维与升级.md)）。HomeVault 把攻击面压到最小，但不能保证绝对安全。
7. **运营商或网络层面的干扰。** 例如 WireGuard 的 UDP 流量被限速或阻断，或者运营商收回了公网 IP。这些影响可用性，但不影响数据安全。
8. **家庭成员中的管理员。** 管理员账户可以管理用户、重置二步验证。请只给真正需要的人管理员权限。
9. **镜像供应链。** 镜像固定到版本标签，但没有固定到内容摘要（digest）。如果镜像源（包括国内镜像加速站）被篡改，理论上可能拉到被替换的镜像。请只使用可信的镜像源。
